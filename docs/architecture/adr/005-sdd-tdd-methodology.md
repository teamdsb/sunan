# ADR-005 SDD + TDD 开发方法

## 状态

`accepted`

## 背景

当前仓库处于极早期，需要先把业务边界、接口和数据结构定义稳定，再进入开发。

## 决策

采用 SDD（先规格）+ TDD（先测试）方法，规格文档作为里程碑开发的前置产物。

## 影响

- 优点：前后端可围绕同一规格并行，需求漂移更易被发现。
- 代价：前期文档投入更高，需要严格维护规格与实现一致性。
- 后续：所有功能开发应遵循“规格 -> 测试 -> 实现 -> 回写规格状态”的闭环。
