# M8 Wave 4 安全主数据中心设计

## 目标与边界

Wave 4 在不破坏现有证书、船舶监控、提醒和工作平台记录的前提下，建立船舶、人员、任职、设备和证书的可追溯安全主数据中心。它不建设设备维护闭环、任务、检查或外部监管集成；这些由后续 Wave 负责。

## 架构

保留既有 `vessels`、`personnel` 与 `certificates` 作为主对象，新增以下可独立演进的关系和治理对象：

- `safety_equipment_categories`：可停用的设备分类，分类代码在未删除记录中唯一。
- `safety_equipment`：设备编码在未删除记录中唯一；关联所属船舶和分类，状态为 `active`、`inactive` 或 `retired`。
- `vessel_personnel_assignments`：人员—船舶任职，记录岗位、上船/下船日期、状态和当时名称快照；同一人员在相交有效期内只能有一个有效的船舶任职。
- `master_data_import_batches` 与 `master_data_import_rows`：以文件 SHA-256 和导入类型控制重放，保存行级结果、自然键、错误、来源和回滚状态。
- `workbench_master_data_references`：保持原始 payload 完整，单独保存原始文本、目标对象、对象显示快照和映射状态。

新对象均有 UUID、审计字段、软删除、外键、部分唯一索引和迁移 `up`/`down`。历史关系使用 `ON DELETE RESTRICT`；停用是状态变更，不物理删除。

## 数据与业务规则

- 船舶编码、船名、人员企业微信 UserId、设备编码、设备分类代码均唯一（软删除记录不参与唯一性）。
- 人员可无企业微信身份；一个 `wecom_user_id` 只映射一个未删除人员。企业微信同步只更新通讯录字段，不覆盖业务任职或备注。
- 新业务引用必须选择 `active` 船舶、在职人员、`active` 设备和有效任职；证书新建/修改同样禁止停用的持有人。
- 历史引用不失效：业务记录保存原始文本和关联时显示快照，主数据停用或改名不会改写历史。
- 证书继续使用现有持有者模型；新增 `equipment` 持有者类型，设备证书通过此关联展示在设备和船舶 360 视图中。

## API、权限与导入

`/api/v1/master-data` 提供船舶、人员、设备、分类、任职、详情、受控搜索选择器、导入批次及文本映射查询。资源写入、停用、导入和手工映射只对系统管理员及被授予安全主数据管理权限的角色开放；普通用户仅能在 Wave 2 ABAC 范围内读取可见且允许暴露的字段。手机号、企业微信身份等敏感字段仅在本人、管理员或有业务管理范围的用户上下文返回。

选择器统一接收 `keyword`、`vesselId`、`asOf` 与 `includeInactive`。普通新建表单固定 `includeInactive=false`；历史详情以关联 ID 和快照读取，不调用新建选择器。所有选择和写入端点均在服务端校验状态、有效期和数据范围，前端隐藏不构成授权。

导入为 JSON/CSV 标准化行的批量操作。请求或文件先计算 SHA-256，再用 `import_type + content_hash` 找到或创建批次；已完成批次直接返回原报告。每行依自然键执行新增、无变化跳过、可更新字段更新或失败；不清除旧值。重复、格式错误、外键缺失、无权限和有效期冲突分别记录，报告可下载。回滚仅撤销此批新建的主数据、关系和映射；更新操作保留前像，因此只能通过显式补偿恢复，不自动覆盖后续人工修改。

## 既有文本引用治理

扫描工作平台 payload 中已登记的船名、人员、设备字段。每个来源字段写入独立映射：`raw_value` 永远保存；精确唯一匹配为 `matched`，多候选为 `ambiguous`，无候选为 `unmatched`，人工选择为 `manual_override`。原 payload 不更新。读取时优先使用映射快照展示，并同时保留原始值用于审计、导出和回滚。

## UI 与移动端

安全主数据入口包含船舶、人员、设备列表；详情页提供证书、任职、设备/所属船舶、历史引用和导入结果。搜索选择器提供输入搜索、加载、空态、权限不足、网络失败和已停用提示；仅在历史查看场景显示已停用对象。移动端选择器以抽屉/全屏搜索展示，不要求用户输入 UUID。

## 测试与验收

先编写失败测试，覆盖唯一性、有效期不重叠、停用拒绝新引用、停用对象的历史快照、企业微信唯一映射、设备外键、导入重放、行级错误和回滚、文本映射保真、敏感字段与 ABAC。使用 PostgreSQL testcontainers 验证迁移和约束；前端覆盖选择器搜索、停用过滤、历史展示、权限不足和重复提交。最终运行 API unit/integration、web tests/build、OpenAPI、migration up/down 和文档索引。

## 迁移与恢复

部署按“schema → 主数据导入 → 文本映射 → 对账 → 开关切换”执行。对账报告包含来源总数、新建/更新/跳过/失败数、每种映射状态、外键可解析率和异常清单。失败不写入或覆盖 source payload。`down()` 仅删除 Wave 4 新增结构；业务数据恢复采用按批次的显式补偿，并始终保留原始工作平台记录、文件和审计。
