# 企业微信头像与权限展示设计

## 目标

让企业微信成员完成网页登录后可靠显示真实头像；让前端只展示当前用户实际可执行的新增、编辑、发布、删除和配置操作。采购单与采购报表保留给所有已认证成员（含船员）新建。

## 头像授权流程

前端企业微信 OAuth 链接使用 `snsapi_privateinfo`。后端以授权码调用 `auth/getuserinfo`，读取短期 `user_ticket`；仅在本次请求内使用该票据调用 `auth/getuserdetail`，并将返回的头像合并到用户资料。`user_ticket` 不写入数据库、不写入日志。

成员读取接口继续作为姓名、部门、职务的组织架构来源。敏感接口只补充真实头像等授权字段。没有 `user_ticket`、成员未授权、或敏感接口暂时失败时，认证不失败；已有的成功头像保留，避免一次临时授权问题清空资料。

后端同时返回本次敏感资料获取是否成功。成功时前端永久记录当前授权版本；失败时只设置 24 小时冷却，到期后自动再次授权，避免立即重定向循环和一次失败后永久放弃头像获取。

企业微信可能返回 HTTP 头像地址。仅对企业微信已知头像域名将协议升级为 HTTPS，避免 HTTPS 页面上的混合内容拦截；其他 URL 原样保留。头像组件加载失败时继续回退到姓名首字。

企业微信后台前置条件：自建应用启用头像敏感字段，成员位于应用可见范围内，并在更新后重新授权登录。实现所依据的官方接口为 `auth/getuserinfo`、`auth/getuserdetail`。

## 系统管理员

系统管理员独立于部门判定。后端从 `WECOM_SYSTEM_ADMIN_USER_IDS` 读取逗号分隔的企业微信 UserID，并在每次签发或刷新登录资料时叠加 `system_admin` 角色。姓名、手机号和部门 ID 均不是有效配置值。

## 权限展示模型

后端始终是授权的最终裁决者；前端只使用能力信息减少无效入口。

通用内容管理角色为总经办、财务部、业务部、船务部、后勤部和系统管理员；待设置部门、公司成员和船员不获得通用内容管理权限。监控端口配置属于系统设置，仅系统管理员可写。安全模板和检查计划沿用后端既有的安全管理规则：船务部或系统管理员可管理。已分配给成员的检查、CAPA 与任务操作继续由记录的 `availableActions` 或责任人关系决定，不能仅依赖部门角色，且后端写接口必须执行同一生命周期门禁。

| 功能 | 普通成员 / 船员 | 部门管理角色 | 系统管理员 |
| --- | --- | --- | --- |
| 采购单、采购报表 | 可新建；仅处理本人记录 | 可新建和执行现有审批职责 | 全部 |
| 证照、企业资料、企业制度 | 查看 | 显示本部门管理操作 | 全部 |
| 船舶监控 | 仅查看启用入口 | 仅查看启用入口 | 显示配置操作 |
| 采购字典、预算配置 | 不显示管理操作 | 按后端既有角色规则显示 | 全部 |
| 安全模板、检查计划 | 不显示新建或发布 | 船务部可管理 | 全部 |

企业资料和企业制度的部门范围从“第一个部门代码相同”改为“所属任一部门代码相同”。新建数据仍记录创建者的首个可用业务部门代码，已有数据不迁移。列表及详情接口返回记录级管理能力，前端据此隐藏不属于本部门的数据编辑、发布和删除按钮。

## 前端行为

创建一个共享权限判断模块，集中表达通用管理、安全管理、采购字典与预算配置权限，替代散落的角色数组判断。其职责只限于页面级入口；业务记录的具体动作使用后端返回的能力。

无页面管理权限的用户仍可查看允许读取的列表和详情，但不渲染表单、抽屉、主要操作按钮或管理型导航入口。直接访问管理页面时显示明确的无权限状态，不发送无意义的管理查询。采购创建入口不受此限制。

## 测试与验收

- 后端：覆盖有/无 `user_ticket` 的 OAuth 资料合并、真实头像持久化、旧头像保留及敏感接口调用体。
- 前端：覆盖 OAuth scope、头像 HTTPS 规范化与失败回退；覆盖普通成员不见管理入口、采购入口仍可见、系统管理员可见全部入口。
- 后端：覆盖多部门用户可管理任一所属部门的企业资料和制度，且其他部门仍被拒绝。
- 回归：API 与 Web 测试通过，生产构建通过。
