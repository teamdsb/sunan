# 升级版操作手册 Markdown 与 Word 交付设计

## 目标

以苏南船舶管理系统 `0.0.5` 的当前源码、页面、权限和现行规格为依据，完善用户操作手册，并交付内容一致的 Markdown 与 DOCX 两种格式。Word 版参考用户提供的《匠芯云链小程序应用软件说明书》的清晰图文组织方式，但不复制其产品内容、品牌或移动端竖图布局。

## 交付物

- `docs/handbook/苏南船舶管理系统操作手册.md`：内容真源，便于版本管理、检索和后续维护。
- `docs/handbook/苏南船舶管理系统操作手册.docx`：A4 纵向正式发布版，包含封面、目录、页眉、页码、图号和 4:3 截图占位。
- 可复现的 DOCX 生成脚本与通用 4:3 占位图资源，保证 Markdown 后续变化可以重新生成 Word，而不是人工维护两份互相漂移的正文。

## 内容证据与范围

手册内容按以下优先级核对：

1. `apps/web/src` 中实际可见页面、字段、按钮、状态和路由。
2. `apps/api/src` 中权限、状态转换、附件、审批、导出和异常边界。
3. `docs/specs` 中标记为当前的领域规格与通用规范。
4. 当前需求文档用于核对业务目的，不把尚未出现在页面中的规划能力写成可操作功能。

本轮重点吸收 `0.0.5` 升级中的企业微信头像与多部门权限、文件格式与系统内预览、附件列表、采购 PDF 预览/导出、报表审批展示、跨模块页面间距和真实按钮显隐变化。

## 手册结构

Markdown 与 Word 使用同一章节顺序：

1. 文档说明与运行条件。
2. 角色、数据范围和职责分离。
3. 企业微信登录、直达和导航。
4. 通用操作，包括查询、表单、状态、上传、预览、下载、解除关联、审批、PDF 和异常恢复。
5. 我的。
6. 办事。
7. 采购管理。
8. 工作平台。
9. 安全管理，包括主数据、计划、任务、检查、问题和 CAPA。
10. 移动端现场操作。
11. 角色快速操作清单。
12. 管理员和支持人员检查。
13. 常见问题与排障。
14. 操作与合规要求。
15. 截图清单。
16. 手册维护。

正文只使用用户和管理员能理解的产品术语，不出现开发阶段、研发批次、待实现路线或内部验收过程等项目管理表述。

## 4:3 截图占位设计

### 单图场景

每个关键页面或关键动作使用一张全宽 4:3 占位图，顺序为：

1. 小节标题与简短用途说明。
2. 4:3 截图占位图。
3. 图号和截图内容说明。
4. 操作步骤。
5. 预期结果。
6. 注意事项或权限说明。

Word 中的占位图使用固定宽度和 4:3 高宽比，居中显示。用户后续可用 Word 的“更改图片”替换单个占位图，尺寸与位置保持不变。

### 多图场景

一个操作需要展示多个状态或连续页面时，使用同一图号下的字母子图，例如“图 7-4A 新建表单”“图 7-4B 提交结果”“图 7-4C 审批轨迹”。

- 每张子图仍保持完整 4:3，不缩成拼图或窄栏。
- 子图按操作顺序连续排列，必要时自然分页。
- 每张子图都有独立的画面说明和替换位置。
- 共同的操作步骤放在图组之后，步骤中引用对应子图编号。
- 同一页面的局部状态变化可以使用两张子图，不要求把所有状态挤进一张截图。

### Markdown 表达

Markdown 中每个截图位置使用醒目的占位块，包含图号、4:3 比例和应截取的页面内容，并引用统一占位图资源。实际截图补齐后，只需替换图片路径与替代文字，不改变章节结构。

## Word 版式

- 纸张：A4 纵向。
- 页边距：上 1.8 cm、右 2.1 cm、下 1.7 cm、左 2.1 cm，沿用参考稿的紧凑公文版式。
- 封面：系统名称、应用软件说明书（用户操作手册）、版本、运行容器、适用对象和核对日期。
- 目录：使用 Word 标题级别生成可更新目录。
- 页眉：苏南船舶管理系统与操作手册名称。
- 页脚：当前页码。
- 标题：黑色为主，使用稳定的三级层级和自动编号兼容样式。
- 表格：细边框、浅色表头、固定列宽，避免跨平台错位。
- 截图：居中、固定 4:3 比例、图题位于图片下方；图组允许跨页，但图题不与对应占位图分离。
- 正文：中文宋体或等效中文字体，英文和数字使用 Arial，保证 Windows、macOS 与 LibreOffice 可读。

## 双格式同步方式

Markdown 是唯一正文真源。DOCX 生成脚本读取 Markdown 的标题、段落、列表、表格、提示块和截图占位标记，映射为 Word 样式。生成过程不修改 Markdown 内容。

当系统升级时，维护者先更新 Markdown，再重新运行生成脚本覆盖 DOCX，并执行结构和渲染验证。DOCX 不作为反向编辑真源，避免两份正文产生差异。

## 验证

### 内容验证

- 对照当前路由和页面清单，确认所有用户可操作模块均有入口、步骤、结果和异常说明。
- 对照权限与状态转换，确认手册不会向无权角色展示不存在的动作。
- 扫描开发阶段、内部规划、占位式需求和其他产品名称，确保正式手册中不出现。
- 检查 Markdown 标题、链接、图片引用、图号和多图子编号无重复或断档。

### DOCX 验证

- 使用 DOCX 校验器检查包结构与 WordprocessingML。
- 转换为 PDF，核对页数、A4 尺寸、目录、页眉、页码、表格和分页。
- 抽查封面、目录、单图页、多图页、长表格页和最后一页渲染结果。
- 检查每个截图占位框的显示比例为 4:3，图题与占位图相邻。
- 从 DOCX 重新提取正文，与 Markdown 的章节和关键内容进行一致性检查。

## 验收标准

1. Markdown 与 DOCX 均位于 `docs/handbook`，标题、版本、章节和业务内容一致。
2. 手册覆盖 `0.0.5` 当前可操作功能和本次升级后的真实交互。
3. 每个关键操作都有可直接替换的 4:3 截图占位；多图流程按字母子图连续编号。
4. 正式手册不包含其他产品内容或研发项目管理术语。
5. DOCX 结构校验、PDF 渲染、文档索引和 Markdown 格式检查全部通过。
