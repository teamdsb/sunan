# M8 Wave 3：证据、打印与异步导出设计

## 目标与边界

为所有工作平台记录及采购执行清单详情提供一致的附件、企业微信拍照、H5 签名、定位、受控 PDF 下载和真实异步导出能力。Wave 3 不删除 OSS 对象或全局 `files` 元数据，不新增外部监管集成，也不将安全领域变成新的一级导航。

Wave 2 的记录级 ABAC 仍是全部读取、上传、下载、打印和导出入口的唯一授权基础；前端显示不构成授权。

## 方案选择

采用“统一证据服务 + 领域授权适配器”。证据、审计和导出任务具有统一数据模型；工作平台通过记录级 ABAC 授权，采购通过现有采购单查看权限和草稿编辑权限授权。该方案避免把安全证据写入非结构化 payload，也避免两个业务域各自复制文件、下载、审计和任务状态逻辑。

## 数据模型

- `evidence_records`：业务对象、文件、类型（attachment/signature/location）、状态、采集人、采集时间、摘要哈希、定位坐标和精度、异常说明，以及可追溯的替换来源。
- `evidence_audits`：不可变审计日志，记录创建、替换、解除关联、归档、下载、失败重试；必须包括操作者、时间、原因、对象类型/ID、文件 ID 和请求 ID。
- `export_jobs`：业务对象、格式、查询快照、状态 `queued|running|succeeded|failed`、重试次数、失败码/信息、结果文件和执行时间。任务在数据库持久化，不使用模拟 fileId 或进程内假任务。
- `wecom_media_transfers`：以 `media_id` 唯一，保存转存状态和失败原因，防止重复转存；失败记录可由原调用者在授权范围内重试。

所有引用 `files.id` 的外键均使用 `ON DELETE RESTRICT`。采购解除关联只删除 `procurement_order_files` 的关联行，同时插入审计；不能删除 `files` 行或 OSS 对象。迁移必须包含可逆 `up/down` 与 PostgreSQL testcontainers 验证。

## 授权与 API

- 文件下载只通过业务作用域接口换取短期 URL：先验证工作平台记录 ABAC 或采购单查看权限，再写下载审计，最后生成 URL；无权时返回 403，且不暴露文件元数据或 URL。
- 工作平台附件绑定、解除关联、签名、定位、打印与导出均先验证记录可见性；改变证据关系另要求当前用户具有相应 `availableActions`。
- 采购新增 `DELETE /procurement/orders/{id}/attachments/{fileId}`，请求体要求非空 `reason`。仅订单创建者或系统管理员、且订单为 `draft` 时可调用；不存在订单—文件关联返回 404，非草稿或无权均由后端拒绝。
- 企业微信拍照链路为 `chooseImage → uploadImage → from-wecom`，使用 `mediaId` 幂等记录。前端在 JS-SDK 配置失败、取消或设备不支持时提供“重试初始化”和普通文件选择，不伪造照片或位置。
- 签名上传后保存签名图片、签署人、签署时间和由业务摘要计算的 SHA-256。定位只在成功采集时提交经纬度与精度；拒绝或失败可提交人工异常说明，但不得提交虚构坐标。
- 工作平台打印生成真正的 PDF 文件，返回受权限保护的 `fileId`、`downloadUrl`、模板版本、业务编号、生成时间和水印信息。PDF 内容包含业务编号、版本、生成时间和配置水印。
- 考勤及通用导出创建真实 `export_jobs`；后台执行器领取 queued 任务并原子更新为 running，成功写入真实结果文件，失败保存可诊断错误。重试是受授权的显式动作，失败任务重新进入 queued。

## 前端交互

新增多文件 `EvidencePanel`，替代工作平台 schema 中的附件说明/手工 fileId 路径。它支持：文件选择、上传进度、企业微信拍照、预览、下载、签名、定位、失败重试，以及带原因和二次确认的解除关联。组件接收领域适配器，而不自行推断角色。

采购详情使用同一展示与预览模式：草稿编辑者可上传和解除关联；解除关联前显示不可逆提示（仅解除当前采购单关联，不删除原文件），要求输入原因，成功后失效查询并刷新列表。其他查看者只在后端授权允许时看到预览/下载。

移动 H5 维持工作台深链可用性、44px 操作热区、上传弱网反馈、加载/空/错误/权限状态。定位失败提供重新授权、重试 JS-SDK 与填写异常说明三条明确恢复路径。

## 测试与验收

先写测试，再实现：

1. API integration：允许/拒绝的文件下载、工作平台附件、采购草稿解除关联、非草稿/无权/不存在关联拒绝、关联解除后 `files` 与其他关联仍在。
2. API integration：签名摘要、定位成功/拒绝/JS-SDK 失败、证据替换/解除/归档审计，以及 `mediaId` 幂等和失败重试。
3. 单元及 integration：导出任务状态机、真实文件、失败信息和受控重试；无权用户不能下载 PDF 或导出结果。
4. Web：证据组件上传、拍照降级、预览下载、解除确认、签名和定位错误恢复；采购成功后刷新。
5. 验证：受影响 API/Web 测试、API/Web build、每个 OpenAPI 验证、文档清单与索引校验。

真机验收不在开发环境中伪造。验收记录必须分别填写 iOS/Android 的机型、系统、企业微信版本、拍照、定位、签名、文件预览结果与截图/录屏索引。

## 明确约束

- 文件关联一律业务作用域授权；不得提供可绕过记录权限的通用下载 URL。
- 归档证据绝不静默覆盖或物理删除；替换、删除和解除关联均需原因与审计。
- 导出状态只使用 `queued`、`running`、`succeeded`、`failed`；客户端轮询状态且不把 queued 当成功。
- 不在本 Wave 直接完成真机操作；该项依赖用户提供可用企业微信 iOS/Android 设备与测试账号。
