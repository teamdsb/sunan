# 全站控件与报表审批单体验优化设计

## 目标

统一全站查询、筛选和同行表单操作中的输入框、搜索框、下拉框、日期选择器、数字输入框与按钮的高度、圆角、边框和响应式对齐；同时将报表审批单详情从技术 JSON 展示升级为业务摘要页面，并将报表审批单 PDF 重做为可预览、打印和归档的正式 A4 业务单据。

本设计采用用户确认的 A 方案“蓝白业务摘要型”，延续现有苏南船舶 OA 控制台和采购单的蓝白视觉语言。

## 已确认范围

### 全站控件

覆盖 `apps/web/src` 内所有面向用户的查询栏、筛选栏、工具栏和同行表单操作，包括：

- 我的模块的证照、企业资料、企业制度和提醒筛选。
- 办事首页搜索、办事搜索页和办事治理台。
- 采购列表、报表、审批、报表审批、预算和字典治理。
- 工作台内的查询、过滤和同行操作区。
- 其他复用 `sunan-query-grid`、`filter-panel` 或领域筛选容器的页面。

正文表单中的同行控件沿用同一高度规则。多行文本框、上传区、表格内紧凑操作按钮、纯图标按钮和分页器不强制拉伸为 `46px`，但必须与相邻同类控件对齐。

### 报表审批单

覆盖：

- 报表审批单详情页面。
- 参数快照和汇总快照的业务化展示。
- 审批进度与审批记录。
- 报表审批单 PDF 生成、应用内预览和下载。
- 桌面端与企业微信移动 H5 响应式布局。

不修改审批节点、权限、报表计算口径、数据库字段或现有 API 路径。

## 全站控件视觉规范

### 几何与间距

- 查询、筛选和同行表单控件统一可视高度为 `46px`。
- 圆角统一为 `10px`；组合搜索框的左右端分别保留外侧圆角，内部接缝不重复圆角。
- 同行控件横向与纵向间距统一为 `12px`。
- 输入框、下拉框、日期选择器和数字输入框在网格中使用 `min-width: 0`，避免长内容撑破容器。
- 桌面端优先同行排列；空间不足时自然换行。移动端改为单列铺满，主操作按钮宽度为 `100%`。

### 颜色与交互

- 默认边框使用浅蓝灰，背景为白色，输入文字使用深蓝黑，placeholder 使用中性灰蓝。
- hover 仅加深边框，不改变控件尺寸。
- focus 使用企业蓝边框和低透明蓝色外轮廓，不造成布局跳动。
- disabled 使用浅灰蓝背景和可读的禁用文字，不用低对比度纯灰。
- 主按钮使用企业蓝；普通按钮使用白底蓝字；危险操作继续使用现有红色语义。

### 搜索组合控件

`Input.Search` 的输入外壳、addon 和搜索按钮共享同一 `46px` 高度。内部 `.ant-input` 不重复设置最小高度，避免输入区高于搜索按钮。边框、圆角和 focus 状态由组合外壳统一管理。

### 实现边界

共享几何与状态规则沉淀到 `apps/web/src/app/app.css` 的通用控件层；页面只保留布局列数和领域差异。清理或收敛与通用规则冲突的高优先级页面选择器，避免继续用页面级覆盖互相修补。

## 报表审批单详情设计

### 页面标题与动作

页面标题使用业务名称，例如“2026年4月采购月报”；副标题展示报表编号、所属部门和“生成时数据快照”说明。

操作区保留：

- 返回采购首页。
- 进入报表审批页。
- 预览 PDF。
- 导出 PDF。
- 草稿创建人或系统管理员可见的提交审批。

桌面端动作右对齐并等高；移动端按重要性换行，提交审批保持主按钮语义。

### 状态概览

首个信息条展示：

- 审批状态。
- 统计周期。
- 所属部门。
- 审批通道。

状态使用紧凑标签，不用大面积高饱和背景。外部流程状态仅在存在外部流程时显示，避免无意义的空字段。

### 核心指标

从 `snapshotSummary` 提取：

- `totalAmount`：采购总额，按人民币千分位和两位小数显示。
- `totalOrderCount`：采购单数。
- `items.length`：汇总维度数量。

字段缺失时显示 `-`，不把未知或加载失败展示成 `0`。

### 参数快照

不再直接 `JSON.stringify`。已知字段按业务标签展示：

- `reportType` → 报表类型。
- `periodYear` 或 `year` → 统计年份。
- `periodMonth` 或 `month` → 统计月份。
- `departmentCode` → 部门范围。

值使用现有本地化映射。未来新增的未知字段进入“其他参数”区域，以安全的键值文本展示，避免静默丢失数据。

### 汇总快照

`snapshotSummary.items` 使用响应式表格展示：

- 汇总维度名称 `label`。
- 采购单数 `orderCount`。
- 采购金额 `amount`。

表格底部增加合计行，合计优先使用快照中的 `totalAmount` 和 `totalOrderCount`。无明细时显示“当前快照没有汇总明细”，不显示空 JSON 或空白卡片。

### 审批进度与记录

根据报表状态展示“创建 → 部门审批 → 财务审批 → 总经办终审”的进度条。退回、驳回和完成状态使用现有审批状态语义。

审批记录继续使用响应式表格，节点本地化为部门审批、财务审批和总经办终审；展示动作、审批人、时间、意见和来源。无记录时显示明确空态。

## 报表 PDF 设计

### 模板结构

新增独立的报表 PDF 模板，不继续使用当前逐行文本 `buildA4Pdf`，也不直接复用采购单业务模板。允许复用底层 PDF 绘制、字体、分页和文本测量辅助函数。

每页包含：

- 苏南船舶管理品牌页眉。
- “采购报表审批单”标题和业务报表名称。
- 报表编号与生成时间。
- 页码和“数据口径：审批单创建时快照”页脚。

正文依次包含：

1. 基本信息表格。
2. 汇总概览指标。
3. 统计条件。
4. 汇总明细表格及合计。
5. 审批记录表格。

金额右对齐并使用人民币格式；中文继续使用现有内嵌字体。汇总明细和审批记录支持跨页续表，续页重复表头。

### 数据来源

PDF 只使用报表实体中的 `snapshotParams`、`snapshotSummary` 和当前审批记录，不重新计算采购数据，避免审批后口径漂移。打印服务在生成 PDF 前读取该报表的审批记录，并传入独立报表模板。

### 预览与下载

保留现有两个独立动作：

- 预览 PDF：生成完成后直接打开应用内 `FilePreviewModal`。
- 导出 PDF：生成完成后通过统一下载帮助函数保存。

禁止使用异步 `window.open`。生成失败时保留页面并显示可重试错误。

## 数据规范化与兼容

前端增加纯函数负责从 `Record<string, unknown>` 安全读取字符串、数字和汇总明细，不信任快照结构。

- 非有限数字不参与金额或数量合计。
- `items` 不是数组时按无明细处理。
- 明细字段缺失时使用 `-`，不抛出渲染异常。
- 未知对象只作为安全文本展示，不执行 HTML。
- 月报缺少月份时显示年份，不编造月份。

后端 PDF 使用相同业务映射原则，但保持独立类型守卫，避免前后端共享运行时代码造成耦合。

## 错误、加载与空态

- 详情加载中显示卡片骨架，不先渲染 `0` 指标。
- 无权限或记录不存在继续显示业务化警告。
- 报表存在但快照为空时，基本信息和审批记录仍可查看。
- 审批记录加载失败不能阻止详情展示；审批区显示独立错误态。
- PDF 生成失败不关闭当前页面、不创建空白窗口，并允许再次点击。

## 测试设计

### 前端

- 通用控件 CSS 策略测试覆盖高度、搜索组合控件和移动端单列规则。
- 报表详情测试覆盖业务标题、状态概览、三项指标、参数本地化、汇总明细和合计。
- 覆盖无明细、未知快照字段、审批记录为空和快照字段异常。
- 保留提交、应用内 PDF 预览、导出下载和直达返回测试。
- 在 `320px`、`390px`、`768px`、`1440px` 和 `1920px` 视口检查控件等高、换行、溢出和详情布局。

### 后端

- 报表 PDF 生成结果为有效 PDF，包含可归档文件记录并回写 `exportPdfFileId`。
- 月报和年报分别覆盖有明细、无明细、多页明细和审批记录。
- 验证 PDF 使用快照值而不是重新查询后的变化值。
- 保留权限、记录不存在和 OSS 持久化失败覆盖。

### 完成门禁

- 受影响页面测试通过。
- 完整 Web ESLint、Web 测试和 Web 生产构建通过。
- 相关 API 单元和集成测试通过。
- 浏览器五档视口验收通过，页面级无横向滚动。
- 实际生成并渲染报表 PDF，人工检查中文、金额对齐、分页、表头和页脚。

## 非目标

- 不改变报表统计计算口径。
- 不改变审批链、权限或通知流程。
- 不增加图表、趋势分析或实时重新计算。
- 不改变采购单 PDF 模板。
- 不引入新的 UI、PDF 或在线预览第三方依赖。
- 不提交或推送 Git 变更，由用户自行处理版本提交。
