# UI 与主分支后端能力边界收口设计

## 目标

保留当前蓝白企业工作风 UI，以 `main` 已实现的后端能力为产品边界。前端不展示、暗示或提供没有真实后端闭环的功能，也不为追求接口覆盖率强行增加 UI。

## 范围

- 审查 `apps/web/src/features` 的生产页面交互、功能文案和空状态。
- 保留已有真实 API 的查询、新增、修改、状态操作、文件、审批、打印和导出能力。
- 删除由 UI 改造自行扩展、但 `main` 后端并未提供的功能表达与入口。
- 不新增数据库实体、迁移、Controller 路由或外部系统集成。

## 办事模块调整

`main` 当前提供分类目录、入口搜索、入口打开、治理台、发布/停用与操作审计。本轮保留这些功能，并进行以下收口：

- 删除“我的办理”占位卡片。
- 删除“继续办理”和“查看审批进度”等未实现描述。
- 搜索提示只描述“办事入口”，不再暗示可搜索表单或审批事项。
- 保留新版移动端布局、分类切换、入口列表和治理台入口。

## 全站合同检查

每个可见命令按以下规则判定：

1. 业务操作必须由 RTK Query API 或受控的对象存储直传链路执行。
2. 对应的 HTTP 方法与路径必须存在于 `main` Controller。
3. 纯路由导航必须指向已注册页面；办事外部入口必须先记录真实打开审计。
4. 不符合上述条件的按钮、入口、指标和功能性文案应删除，不用 mock 或“暂未开放”占位。

## 错误与空状态

- API 失败时显示可理解的错误提示，不用固定数字或伪造记录兜底。
- 真实查询返回空数组时保留中性空状态。
- 不把“后端尚未实现”之类开发说明展示给业务用户。

## 验证与交付

- 更新受影响的页面和路由测试。
- 重跑前端测试、生产构建、后端测试与 lint。
- 重跑前后端方法+路径映射和生产包 mock/旁路扫描。
- 检查移动端与桌面端办事首页，确保删除占位后布局没有断层或多余间距。
- 单独列出被删除或改写的 UI 功能表达，后端接口数量不应因本轮收口发生变化。
