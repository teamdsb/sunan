# M9 迁移、发布与兼容回滚操作包

本文是操作步骤，不是生产执行记录。W5 仅在本地合成 PostgreSQL/企微 transport 上演练；真实租户、三端和生产恢复状态见 [W5 验收](../acceptance/M9-wave-5.md)。生产发布须另行授权，禁止直接运行仓库历史 `output/release-*` 脚本作为本次发布。

## 1. 发布前与停机边界

1. 固定待发布源码提交、API/Web 镜像摘要、当前 schema/migrations 版本及全部 API/worker 实例清单，完成本次质量门禁与现场矩阵；本地未提交工作树不能作为生产镜像标识。
2. 由运维记录主应用 CorpID、AgentID、env 管理员名单和目标企业成员数，凭据通过受控渠道核对，不贴入验收日志。主应用 OAuth、回调、JS-SDK、通讯录和安全参数仍走 env。
3. 首次迁移前暂停 API 写入及可能发送通知的 API、证书提醒 job、计划任务 scheduler/worker、采购提交/审批/重试入口。当前证书/计划 scheduler 在 API 进程内，不能只停一个所谓独立 worker；多实例均须纳入。使用维护页面阻断用户访问，暂停上游回调转发时应按既有机制保留待处理事件，恢复后对账。
4. 列出 `sending/uncertain` 投递，外部结果不确定的先留待核对，不把进程停止解释为发送失败。待事务退出后再备份；避免一边恢复一边由旧实例写入或推送。

## 2. 身份预检和基线留存

在受控数据库连接中使用 env 的真实 CorpID 执行只读检查（连接凭据由既有凭据管理提供，不放命令行或日志）：

```bash
psql -X -v ON_ERROR_STOP=1 -v expected_corp_id="$WECOM_CORP_ID" -f scripts/m9-preflight.sql
```

脚本可用于 W2 前后 schema；输出用户总数、跨企业/空身份、重复 UserID、异常来源 JSON 数量、设置/人事关联孤儿数和实际声明的外键。身份/来源形状异常退出非零；关联孤儿数必须由业务核对，不自动删除或补账号。没有声明 FK 的 UserID 关系不冒称已具备数据库外键约束。

停机窗口另行受控留存下列基线，逐 UserID 对比而非按姓名合并：

- `wecom_users.id/user_id/corp_id`、部门/职位来源快照及迁移前登录角色；历史未知登录时间保持未知，不用 `created_at` 推测从未登录。
- `user_settings.user_id`、`personnel.wecom_user_id`，以及业务创建人、审批人、参与人/船舶任职、历史部门快照和已声明 FK 的数量及关联；历史快照不随平台改部门重写。
- 业务旁路差异：部门 8 的登录角色为 `crew`，`shipping_dept` 不再使提醒/采购收件人额外得到 `shipping`；历史管理员快照不授权；人工财务部门 + 人工 `shipping` 仅有该人工业务角色，部门范围仍为财务；空角色/空部门不回填。受影响未结任务由业务安排交接，平台不会自动移交。

## 3. 备份与密钥恢复材料

使用既有数据库备份机制制作完整一致性 `pg_dump -Fc`（或等价受控备份），记录校验和、时间、schema、迁移账本和恢复验证数据库；受控保存所有业务表，不仅备份新增表。重点包括：

- 用户来源与人工部门/角色、停用、授权版本及 `wecom_user_change_audits`、部门字典、同步批次和来源序列。
- `notification_app_configs` 的加密 Secret 和版本、`notification_app_config_audits`、`notification_delivery_attempts` 的原去重键/状态/尝试历史，以及证书和任务的业务投递/确认记录。
- 主应用 env、管理员 env、当前/上一代通知加密密钥通过独立受控渠道备份，和数据库备份分开存储；数据库审计不存明文 Secret。env 主应用 Secret 不复制入库。

记录所有实例、数据库和 Redis 曾使用的通知配置最高版本。恢复旧备份会同时恢复旧版本号，不能立刻恢复流量；见第 6 节的版本递增步骤。若无法确定最高版本或恢复点之后的人工撤权/停用，保持维护，先核对变更与投递记录。

## 4. 迁移与启用

1. 在测试恢复库执行 `pnpm --filter api migration:run`，确认 migration 账本和预检结果后，才由运维按已批准发布流程执行目标环境迁移。不得启用 `synchronize:true`、重建数据库或重跑 seed 覆盖生产。
2. W2/W4 为增量 migration。迁移后对照数量、UUID/UserID、历史业务关系、默认 follow_wecom/auto/enabled、未知登录事实；通知默认无覆盖，仍用完整主应用 env。
3. 所有 API/worker 一起切换到支持 M9 的代码、env 和密钥集合，确认没有旧进程继续运行；如调整 env 管理员名单，所有实例必须重载后用旧会话和后台收件人分别验证。
4. 管理员先核对目录覆盖提示，再同步并与企微管理员核对全企业目标成员及未登录成员。`unverified`、局部成功或只取得 token 均不能签署全目录/送达通过。
5. 按 W5 U1-U9/C1-C4/R1、三端和独立应用矩阵验收后，分阶段恢复访问、回调和各类推送，观察错误率、权限拒绝、配置版本和不确定投递。配置错误时修复覆盖，禁止自动切主应用。

## 5. 兼容代码回滚准入

不能把“旧镜像能启动”当作兼容。候选版本必须在恢复库同时通过以下项目：

| 维度 | 必须保留的行为 |
|---|---|
| 授权 | env 管理员唯一来源，人工角色替换自动角色，空角色、人工部门和停用不能被 OAuth/同步/旧 token 绕过；来源不可用约束仍生效 |
| 数据 | UUID、UserID、版本/审计、来源顺序和历史参与关系不变，不删除人工设置 |
| 通知 | 独立覆盖/加密可读取，错误不回退；新尝试按当前配置、缓存按企业/应用/版本隔离；实际发送一次使用同一快照 |
| 投递 | 原去重键和历史保留；成功不重发；不确定先人工核对；重试再次核验当前业务资格 |

本轮只证明当前源码恢复后的这些本地行为，没有提供已签署的旧兼容镜像。无法证明上述全部条件时，保持 API/推送入口及所有 scheduler/worker 停止，保留新 schema 和人工设置，修复或构建兼容补丁后重验。禁止启动忽略新字段的旧程序，也禁止通过清空覆盖/恢复旧角色来让旧程序工作。

W2 `down()` 在已有人工设置、来源状态、同步字典/批次或审计时拒绝删除；W4 在配置/审计/投递存在时拒绝删除。保护不是自动回滚方案。即使某张表为空，人工启用后通常仍须保留新 schema，不能为了绕过保护删除业务记录。

## 6. 故障恢复与版本递增

### 只回滚配置内容

保持数据库与去重历史，用管理员配置 API/页面将经核对的历史 AgentID 与匹配 Secret 重新保存，携带**当前** `expectedConfigVersion`；生成更大版本。清除覆盖必须是明确动作，也会递增版本；不要把版本号 SQL 改小或复制旧缓存。

### 密钥故障或轮换

- 只有无覆盖时允许不配置独立密钥继续使用主应用。覆盖存在而无法解密时，保留故障并停止相关发送；不清覆盖来掩盖错误。
- 从独立受控备份找回能解密现有密文的密钥，先在恢复库核验。轮换时所有实例具备新 `SYSTEM_SETTINGS_ENCRYPTION_KEY` 和旧 `SYSTEM_SETTINGS_ENCRYPTION_KEY_PREVIOUS`，调用 `POST /api/v1/settings/notification/encryption-key/rotate` 重新加密；配置版本递增且审计只含非敏感字段。
- 确认所有实例使用新密文、新版本且备份恢复验证通过后，才移除上一代运行时密钥；受控历史恢复材料按保留策略保存。任何阶段无法确认则维持暂停推送。

### 整库恢复

1. 保持访问和全部推送暂停，将备份恢复到隔离库；预检并比对恢复点之后的人工撤权、停用、配置和投递。恢复库不能直接覆盖唯一现库，保留故障库及证据。
2. 恢复点之后的成功消息和不确定结果必须合并核对，不能丢弃后自动再发；恢复点之后的人工撤权/停用必须补齐，不能扩大权限。无法确定的交由业务/运维人工处理。
3. 在仍停流量时，用历史配置内容重复走正常保存 API，直到 `configVersion` **严格大于** 备份与现网/Redis 曾用最高版本；这些中间保存不得有发送者运行。没有独立覆盖也可用明确清除动作递增版本，不复用旧 token 键。不直接回退授权版本，人工授权通过正常编辑产生新版本。
4. 完成新旧密钥核验、UUID/关联/审计/投递对账，使用已验证兼容代码重启所有实例；再按第 4 节恢复。合成演练备份版本1、曾用版本2、恢复后版本3，不代表生产版本值。

## 7. 本地重演

使用仓库要求的 Node 20、pnpm 和运行中的 Docker，企业微信调用均合成，Testcontainers 建库并在退出时销毁：

```bash
pnpm --filter api test:integration --runTestsByPath test/m9-wave5-migration.integration.spec.ts test/m9-wave5-acceptance.integration.spec.ts
```

浏览器专用隔离 API（仅绑定回环地址、仅允许 NODE_ENV=test；测试进程 env 与真实 env 文件分离）：

```bash
cd apps/api
NODE_ENV=test NODE_PATH=. pnpm exec ts-node --files test/m9-wave5-rehearsal.ts
```

另开本地 Vite，明确指向 `http://127.0.0.1:4319/api/v1`，不要把真实前端连接到演练库。演练网关的 `admin/member` code 仅用于测试；不能部署此 harness，也不作为认证安全策略。结束时关闭两进程和浏览器会话。实际执行命令、日志和截图见 W5 验收证据。
