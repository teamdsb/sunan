# "我的"模块 QA 测试指南

## 适用范围

本文档用于 M1 "我的" 模块进入 mock 模式开发与 QA 手动测试阶段时的环境搭建、场景执行和质量评估。

适用对象：

- QA 测试工程师
- 使用 AI 工具辅助测试的研发人员
- 需要在本地复现问题的产品或开发同学

## 环境搭建

### 前提条件

| 组件 | 建议版本 |
|---|---|
| Node.js | 20 LTS |
| pnpm | 9+ |
| Docker Desktop | 最新稳定版 |

### 快速启动

1. 安装依赖：`pnpm install`
2. 启动数据库：`make db-up`
3. 执行 migration：`make migration-run`
4. 初始化种子：`make seed`
5. 启动服务：`make start-api` 与 `make dev`

默认服务地址：

- API: `http://127.0.0.1:3000`
- Web: `http://127.0.0.1:5173`

### Mock 模式说明

前端支持通过环境变量跳过企微认证：

```bash
VITE_LOCAL_BYPASS_AUTH=true
```

开启后，前端会自动创建本地预览用户，默认角色为：

- `all_authenticated`
- `shipping`

该用户用于本地页面联调和 QA 手动测试。

### Mock 模式限制

- mock 用户默认只有船务相关权限，无法覆盖财务、总经办、后勤等全部角色分支。
- 涉及真实企微 OAuth2、JS-SDK、组织通讯录映射的能力，仍需在真实环境补测。
- 若测试用例依赖更高权限，应通过种子数据、数据库调整或真实登录方式补充验证。

### 数据库重置

当数据被污染或需要重新回到初始状态时，执行：

```bash
make db-reset
make migration-run
make seed
```

## 自动化测试覆盖说明

### 已覆盖，无需手动重复

- 单元测试：规则函数、状态计算、格式化逻辑
- 集成测试：主要 API 与数据库真实行为
- 组件测试：核心页面交互、加载和提交行为

### 仍需手动测试的领域

- 视觉回归与版面稳定性
- 企业微信 JS-SDK 相关行为
- 真实设备兼容性
- 弱网与异常网络表现
- 打印与导出体验

## 通用测试检查项

每个子功能至少补充检查以下通用项：

- 分页：页码、页大小、总数、翻页后数据是否正确
- 空状态：无数据时文案、占位和操作提示是否合理
- 加载状态：骨架屏或 loading 是否明确，是否存在闪烁
- 错误状态：接口失败后是否给出可理解提示，是否支持重试
- 软删除不可见：被删除数据不应出现在默认查询结果中
- 时区：所有时间按 `+08:00` 口径展示与计算
- 响应格式：接口是否保持统一 API 信封格式

## 评估标准

| 维度 | 权重 | 关注点 |
|---|---|---|
| 功能完整性 | 40% | 6 个子功能可访问，CRUD 完整，权限正确 |
| 数据准确性 | 20% | 种子数据正确（11 船 1 车），到期计算准确，分页 meta 正确 |
| 用户体验 | 20% | 加载小于 2 秒，无布局错位，中文正确，移动端适配 |
| 稳定性 | 20% | 无崩溃，重复提交防护有效，并发操作无异常 |

建议评分方式：

- 90-100：可进入验收或预发布
- 75-89：存在少量中低风险问题，可排期修复后复测
- 60-74：存在明显缺陷，不建议继续流转
- 60 以下：核心功能或稳定性不达标，需要回归开发

## AI 工具辅助测试指南

### Claude Code 用法

适合以下辅助工作：

- 根据 spec 生成手动测试用例草稿
- 对照 OpenAPI 检查接口契约是否一致
- 基于现有测试文件分析覆盖盲区

示例提示词：

```text
请根据 docs/specs/my/ 下的规格，为“电子证照”模块生成一组 QA 手动测试用例。
要求覆盖 CRUD、搜索筛选、到期状态、附件绑定、异常场景，并按 P0/P1/P2 标注优先级。
```

```text
请对照 docs/specs/my/api/certificate-api.yaml 与当前前端调用行为，
列出参数、响应结构、状态码上的不一致点，并给出需要补测的场景。
```

### Prism Mock Server 用法

当后端接口尚未全部可用时，可基于 API 规格独立验证前端页面行为：

```bash
npx @stoplight/prism-cli mock docs/specs/my/api/certificate-api.yaml
```

适用场景：

- 前端独立联调列表、详情、空状态、错误状态
- QA 提前熟悉页面路径与基础交互
- 校验前端是否依赖未约定字段

### 覆盖盲区分析建议

让 AI 工具重点关注以下问题：

- 是否遗漏权限差异场景
- 是否遗漏弱网、超时、重复提交场景
- 是否遗漏文件上传和下载失败场景
- 是否遗漏移动端布局与长文本换行问题

## 输出建议

QA 提交测试结果时，建议至少包含：

- 测试日期与环境
- 使用账号与角色
- 执行范围
- 缺陷列表与严重级别
- 最终评分与是否建议通过
