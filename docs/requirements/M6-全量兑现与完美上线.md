# 里程碑 6 需求文档：全量兑现与完美上线

## 1. 文档定位

本文件定义里程碑 6 的目标、范围边界、企业微信正式上线口径、生产交付要求与补料门禁，用于指导 M6 的 SDD 更新、代码兑现、联调验收、正式切换与上线后一周的 Hypercare。

M6 承接 M1-M5，目标从“可运行、可联调、可留痕”切换为“与原始需求逐项对齐、在企业微信正式可用、具备生产交付与运维闭环”。

## 2. 里程碑目标

### 2.1 主目标

- 完成工作平台已冻结模块与当前代码实现之间的差异收口。
- 将工作平台从单页壳层升级为可直达的模块化路由与可维护页面结构。
- 完成企业微信正式上线所需的配置矩阵、回调安全、模板绑定、真机回归、切换 runbook 和上线材料。
- 完成生产交付侧的部署、回滚、备份恢复、值班与可观测规格。
- 将 `海图更新` 落地为真实模块；将 `财务板块` 以补料门禁方式纳入 M6，不允许凭空发明字段。

### 2.2 成功标准

- `docs/execplans.md`、`docs/M6-execplans.md`、`docs/requirements/M6-全量兑现与完美上线.md` 构成 M6 主文档入口。
- 工作平台新增模块编码、路由、模块矩阵、统计口径、权限边界与实际代码一致。
- 企业微信后台配置、环境变量、回调安全、模板绑定与系统实现一一对应。
- 发布、回滚、备份恢复、真机回归、上线材料与 Hypercare 具备可执行文档。
- `海图更新` 已进入 API/DB/UI/state 范围；`财务板块` 若缺样表，则以 blocker 文档阻塞开发而不是生成通用表单。

## 3. 范围说明

### 3.1 纳入范围

#### 工作平台全量兑现

- 拆分 `business_operation_flow` 为独立业务模块编码，并在代码与规格中同步落地。
- 新增工作平台路由：`/workbench/modules/:moduleCode`、`/workbench/records/:recordId`、`/workbench/statistics/attendance`、`/workbench/approvals`。
- 统一工作平台首页、模块页、详情页、统计页、审批页的页面层次与测试入口。
- 处理已有 `business_operation_flow` 历史数据的迁移与兼容展示。

#### 企业微信正式上线

- 固化企业微信生产配置矩阵：可信域名、JS 接口安全域名、OAuth 回调域名、消息接收配置、审批模板绑定、应用可见范围。
- 固化回调安全：签名、时间窗、nonce、幂等、可选加密解密、来源 IP 白名单、异常留痕、人工重试、批量对账。
- 扩展真机回归范围至“我的 / 办事 / 采购管理 / 工作平台”四大板块。

#### 生产交付与运维

- 发布顺序、迁移顺序、seed 策略、回滚条件、备份恢复、值班与联系人、上线材料清单。
- 固定关键可观测面：OAuth2、JS-SDK、审批桥、消息、文件、导出、打印。
- 补充性能门禁与企业微信弱网体验约束。

#### 海图更新与财务板块

- `海图更新` 进入 M6 真正开发范围。
- `财务板块` 进入 M6 补料范围：若仓库和原始资料中无样表，不得冻结字段级接口、数据库结构和页面表单。

### 3.2 不在 M6 首批范围

- 将系统形态切换为企业微信小程序。
- 将采购管理整体切换为企业微信原生审批主链路。
- 重写 M1-M5 历史需求文档与历史验收归档。
- 为 `财务板块` 人工编造原始需求中不存在的字段、流程或导出模板。

## 4. 关键决策

### 4.1 工作平台模块拆分以业务语义为先

M4/M5 已冻结业务矩阵，但当前代码仍保留聚合模块。M6 统一采用以下模块编码：

- `business_signin_desk`
- `business_receiving_workgroup_flow`
- `business_oil_boom_operation`
- `business_ship_garbage_operation`
- `business_ship_oily_water_operation`
- `business_domestic_sewage_operation`
- `shipping_chart_update`
- `finance_business_board`（仅在补料完成后进入开发）

### 4.2 旧模块兼容但不再作为新入口

- `business_operation_flow` 进入 legacy-only 状态。
- 新建入口、模块卡片、默认统计口径全部使用新模块编码。
- 旧记录允许通过详情页访问，但不再作为默认新建入口。

### 4.3 财务板块实行补料门禁

- 若未找到原始样表或字段样例，则只允许输出 blocker 文档。
- blocker 未解除前，不新增 API/DB/UI/state 规格，不落地代码，不提供空壳页面。

## 5. 企业微信约束

M6 继续以企业微信官方开发文档为依据，并在文档中统一保留以下链接：

- 网页授权：<https://developer.work.weixin.qq.com/document/path/91335>
- 构造网页授权链接：<https://developer.work.weixin.qq.com/document/path/91022>
- 获取访问用户身份：<https://developer.work.weixin.qq.com/document/path/91023>
- 回调配置：<https://developer.work.weixin.qq.com/document/path/90930>
- 发送应用消息：<https://developer.work.weixin.qq.com/document/path/90236>
- 审批流程引擎：<https://developer.work.weixin.qq.com/document/path/90269>
- 获取审批模板详情：<https://developer.work.weixin.qq.com/document/path/91982>
- 获取审批申请详情：<https://developer.work.weixin.qq.com/document/path/91983>

M6 固定约束如下：

- H5 页面仅在企业微信可信域名下运行。
- OAuth2、JS-SDK、消息接收、审批回调与模板绑定必须形成配置矩阵。
- `WECOM_CALLBACK_TOKEN` 为标准配置名，`WECOM_TOKEN` 仅作为历史别名说明。
- 若启用加密回调，必须提供 `WECOM_ENCODING_AES_KEY`。
- 正式环境需要维护 `WECOM_CALLBACK_ALLOWED_IP_RANGES` 并在接收端完成来源 IP 校验。

## 6. Wave 规划

### Wave 1：M6 文档冻结与差异基线

- 新增 M6 需求文档与执行计划。
- 更新工作平台 README，显式记录“规格已冻结但代码未完全兑现”的差异。
- 新增企业微信生产交付规格：配置矩阵、回调安全、模板绑定、切换 runbook、上线材料清单。
- 更新部署、安全、联调文档。

### Wave 2：工作平台模块全量兑现

- 落地新模块编码与旧模块迁移兼容。
- 新增模块化路由与工作平台页面拆分。
- 落地 `海图更新`。
- 对 `财务板块` 执行补料门禁判定。

### Wave 3：企业微信生产集成闭环

- 环境变量标准化。
- 回调安全、IP 白名单、可选加密解密、模板绑定清单与管理员操作入口收口。
- 真机回归覆盖四大板块。

### Wave 4：部署、运维与可观测性交付

- 生产环境矩阵、发布/回滚/备份恢复 runbook。
- 指标、告警、值班、恢复 SOP 和上线材料清单。

### Wave 5：测试、性能与上线门禁

- 补 workbench 前端测试。
- 所有变更 OpenAPI 纳入校验。
- 后端 integration 的 Docker/testcontainers 前置条件文档化。
- 路由级拆包与弱网体验门禁纳入验收。

### Wave 6：上线切换、验收归档与 Hypercare

- 形成上线包、验收归档与上线后一周的 Hypercare 记录模板。
- 每个 wave 对应 `acceptance-m6-waveN.md`。

## 7. 验收要求

1. 工作平台模块矩阵、代码、页面、权限、统计口径保持一致。
2. 企业微信后台配置与系统 env/config 一一对应。
3. `海图更新` 已落地为真实模块并支持资料留存。
4. `财务板块` 若无样表，必须存在 blocker 文档并阻塞开发。
5. 发布、回滚、备份恢复、真机回归、上线材料可直接执行。
6. M6 以“正式切换完成 + 交付物可审计 + 缺陷闭环完成”为结束条件。
