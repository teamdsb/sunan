# 里程碑 6 需求文档：全量兑现与完美上线

## 1. 文档定位

本文件定义里程碑 6 的目标、范围、成功标准和实施边界，用于将当前系统从“首批可上线”推进到“总需求文档全量兑现、工作平台高保真业务成品、企业微信可完美发布”。

M6 的定位不是继续补底座，而是完成业务本体、遗留模块、管理后台和生产上线闭环，作为全系统正式发布前的最后一轮完整交付里程碑。

## 2. 里程碑目标

### 2.1 主目标

- 让 `docs/需求文档.md` 中的四大板块达到可验收的全量兑现状态。
- 将工作平台从“模板化底座 + 通用页面”升级为“高保真业务成品 + 独立模块页面 + 可实际投产操作”。
- 完成 `财务板块`、`海图更新` 两个遗留模块的真实需求收口与实现。
- 完成工作平台管理员运维台，打通审批异常、导出、对账、诊断和消息一致性。
- 完成企业微信生产参数、真机回归、UAT、上线材料和回滚方案，达到完美上线条件。

### 2.2 成功标准

M6 完成后，必须同时满足以下条件：

1. `我的`、`办事`、`采购管理`、`工作平台` 四大板块均可作为正式环境功能交付。
2. 工作平台核心模块不再只依赖统一通用页，而是具备模块级高保真页面、字段、流程和打印模板。
3. `财务板块`、`海图更新` 从边界文档进入真实实现，并通过业务验收。
4. 工作平台管理员可在系统内完成审批检索、异常重试、导出触发、财务对账和关键链路诊断。
5. 企业微信生产配置、审批模板、消息模板、真机证据、上线材料、回滚预案全部闭环。
6. 系统通过全量自动化测试、关键链路冒烟、真机回归和业务 UAT。

## 3. 范围说明

### 3.1 纳入范围

#### 工作平台高保真业务化

- 将工作平台各业务模板模块升级为真实业务成品。
- 为高频模块提供独立页面、独立交互、独立打印模板和高保真字段结构。
- 收口待办、消息、审批状态、打印快照、导出结果的一致性。

#### 遗留模块实现

- `财务板块`：完成业务边界确认、字段设计、API、页面、导出和权限接入。
- `海图更新`：完成台账规格、页面录入、附件、确认记录和归档检索。

#### 管理后台与运维闭环

- 工作平台管理员控制台。
- 审批异常检索、单实例重试、批量对账、导出任务查询、失败诊断。
- 消息失败、审批失败、JS-SDK 签名失败、导出失败等链路的可视化排障入口。

#### 企业微信正式发布闭环

- 生产域名、可信域名、OAuth2 回调、JS-SDK 域名、审批回调、消息回调配置。
- iOS / Android 企业微信真机回归。
- 上线材料包、回滚方案、联系人和值班机制。

### 3.2 不在 M6 范围

- 新增第五大业务板块。
- 引入预算系统、供应商主数据平台、BI 大屏等新业务域。
- 对历史 M1-M5 归档文档做重写式改造。
- 在缺少业务资料的情况下发明新流程、新字段或新统计口径。

## 4. 关键问题与 M6 对策

### 4.1 当前最大问题

当前系统的主要差距不是底座稳定性，而是：

- 工作平台大量模块仍停留在模板化通用页，尚未形成高保真业务成品。
- 部分字段仍低于原始纸质表单和真实业务记录本的还原度。
- `财务板块`、`海图更新` 尚未进入真实开发。
- 工作平台管理员运维能力以后端接口为主，前端控制台未完整形成。
- 企业微信上线检查模板已具备，但生产配置与证据留存尚未实际闭环。

### 4.2 M6 的总体对策

M6 采用以下策略：

1. 先补齐真实业务输入和高保真 SDD，而不是直接泛化开发。
2. 按模板和部门分 wave 完成工作平台业务化页面。
3. 将遗留模块和管理员控制台纳入正式开发范围，不再后置。
4. 将企业微信生产配置、真机回归、UAT 和上线材料作为里程碑内交付物，而非上线前临时补做。

## 5. 核心交付定义

## 5.1 高保真业务成品的定义

某工作平台模块只有在满足以下条件后，才算 M6 完成：

- 字段与原始需求、样表、记录本或业务提供样张一致。
- 具备独立页面，而不是只靠通用动态表单。
- 支持真实查询、筛选、详情、动作、附件、打印和归档。
- 审批、消息、待办、统计与权限表现一致。
- 通过模块级自动化测试和业务 UAT。

## 5.2 完美上线的定义

系统只有同时满足以下条件，才可定义为“完美上线发布”：

- 总需求文档全量兑现。
- 工作平台各核心模块达到高保真业务成品标准。
- 企业微信生产配置和真机回归证据齐备。
- 上线材料、值班机制、回滚方案、初始化数据与审批模板清单齐备。

## 6. M6 重点交付对象

### 6.1 工作平台高频模块

优先纳入 M6 第一批开发与验收的高频模块：

- 业务部：签船记录表、船舶动态记录表、作业人员签到台、接收工作组操作流程
- 船务部：船员考勤、值守记录系统、航次计划审批、燃油加注
- 总经办：岗前培训、会议管理、安全隐患排查管理
- 财务部：统计中心、财务板块

### 6.2 工作平台剩余模块

M6 中期必须完成以下模块的高保真化：

- 总经办：安全月活动、年度工作计划
- 业务部：围油栏、垃圾、污油水、生活污水接收
- 船务部：船员培训学时统计、船舶自查排查、船舶检验、船舶演练系统、密闭空间、岸基叫应、船员会议记录、污油水接收作业、海事安检系统、案例警示学习、海图更新
- 后勤部：仓库、办公室、食堂、宿舍、车辆维修保养
- 工作组：中船工作组、平陆运河工作组五步作业闭环

## 7. 验收要求

1. 所有工作平台核心模块均完成模块级独立页面和高保真字段收口。
2. `财务板块` 与 `海图更新` 完成真实实现，并进入正式测试范围。
3. 工作平台管理员控制台可执行审批诊断、重试、对账、导出和异常排查。
4. 企业微信 iOS / Android 真机回归通过，且留痕完整。
5. 系统通过全量自动化测试、冒烟测试和业务 UAT。
6. 上线材料可直接提交，不再需要额外补文档。
