# 里程碑 4 需求文档：工作平台全量业务实现

## 1. 文档定位

本文件将里程碑 4 的“工作平台”从占位需求重构为可执行范围说明，用于指导后续 SDD、开发排期、联调验收与企业微信上线准备。

M4 的目标不是单一试点，而是完成工作平台全量业务实现，并按多个 wave 分阶段上线。

## 2. 目标与原则

### 2.1 里程碑目标

- 完成工作平台全量业务模块的规格冻结与分波实施。
- 建立统一的工作平台公共底座，承载模块注册、待办、消息、附件、打印、日志与统计。
- 统一收敛 6 类业务模板，避免每个模块各自建设私有模型。
- 审批类业务以企业微信原生审批为真源，系统内只保留业务镜像、上下文展示和归档检索。
- 全量模块以企业微信 H5 为主使用场景，优先保证移动端操作体验。

### 2.2 实施原则

- 分 wave 上线，不追求同一天交付全部模块。
- 先做平台底座，再按业务模板和部门分批实现。
- 高保真承接现有线下表单、记录本、审批表和统计口径，不凭空扩展未定义业务。
- 能增量补充现有文档时不改动已稳定的基础文档。

## 4. 通用业务抽象

### 4.1 统一模板模型

工作平台所有模块必须先映射到业务模板，再落具体字段和流程规则：

1. `ledger_form`
   - 适用于培训、会议、记录表、计划、学习、值守等台账/资料留存型业务。
   - 强调表单录入、附件留存、打印归档、期限查询。
2. `operation_flow`
   - 适用于班前会、作业前检查、巡查、完工确认等多步骤作业闭环。
   - 强调步骤推进、现场拍照、签认和完工确认。
3. `inspection_rectification`
   - 适用于隐患排查、自查、检验、海事安检、密闭空间、作业检查整改。
   - 强调检查项、整改闭环、整改前后照片与审核结论。
4. `attendance_statistics`
   - 适用于考勤、打卡、作业时长和统计报表。
   - 强调记录采集、口径统一、月度汇总、导出和对账。
5. `service_asset`
   - 适用于仓库、食堂、宿舍、办公室、车辆、设备保养与油耗管理。
   - 强调资产台账、维护保养、消耗统计和生命周期追踪。
6. `wecom_approval`
   - 适用于航次计划、燃油加注、设备审批等强审批业务。
   - 审批状态以企业微信审批实例为真源。

### 4.2 两类基础流程

工作平台中的单据流程仅允许落在以下两类基础方向：

1. 管理人员提单，执行人员落实并记录。
2. 执行人员提单，管理人员审批。

模板配置必须显式声明发起方、执行方、审核方及是否启用企业微信审批。

## 5. 平台级能力范围

M4 工作平台公共底座需统一提供：

- 模块注册与权限可见性
- 工作平台首页与部门入口
- 待办中心与按角色聚合视图
- 通用单据列表、详情、操作日志
- 附件上传、图片对比与文件留存
- A4/A3 打印快照
- 企业微信应用消息提醒
- 企业微信审批发起、回调、状态同步
- 通用统计看板与导出
- 企业微信 H5 真机联调与上线清单

## 6. 企业微信约束

M4 必须遵循企业微信官方文档要求：

- 网页授权：<https://developer.work.weixin.qq.com/document/path/91335>
- 授权链接：<https://developer.work.weixin.qq.com/document/path/91022>
- 获取用户身份：<https://developer.work.weixin.qq.com/document/path/91023>
- 获取 `access_token`：<https://developer.work.weixin.qq.com/document/path/91039>
- 回调配置：<https://developer.work.weixin.qq.com/document/path/90930>
- 发送应用消息：<https://developer.work.weixin.qq.com/document/path/90236>
- JS-SDK：<https://developer.work.weixin.qq.com/document/path/90514>
- JS-SDK 签名算法：<https://developer.work.weixin.qq.com/document/path/90539>

冻结前提如下：

- H5 页面仅在企业微信可信域名下运行。
- JS-SDK 签名与票据处理统一由后端生成。
- 审批类模块必须定义审批模板编码、实例映射、回调同步与对账规则。
- 真机联调必须覆盖企业微信 iOS 与 Android 容器。

## 7. 验收要求

M4 规格层必须先定义以下验收面：

1. 所有模块入口在企业微信内按权限正确显示。
2. 各业务模板均可跑通主流程，无模板外特例链路。
3. 审批类模块能稳定发起、回调、同步、展示和归档。
4. 检查整改类模块支持整改前后照片与关闭归档。
5. 台账类模块支持高保真字段录入、查询、打印与资料留存 3 年。
6. 统计类模块支持月度汇总、导出与口径校验。
7. 资产服务类模块支持维护保养、燃油/消耗追踪与历史检索。
8. 应用消息、待办和审批状态三者一致。
9. 全平台在企业微信移动端通过真机验收。

## 8. Wave 规划

### Wave 1：M4 需求重构与 SDD 冻结

- 重写本需求文档，明确全量范围、模块矩阵、模板分类和上线原则。
- 补齐 `docs/specs/workbench/` 下 API/DB/State/UI 规格索引和骨架。
- 更新 `docs/execplans.md` 为 M4 长周期计划。

### Wave 2：工作平台公共底座 + 企业微信集成底座

- 建立模块注册、入口可见性、待办中心、消息中心、附件、打印和日志的统一规格。
- 将企业微信原生审批桥从采购预留升级为工作平台通用桥接规格。
- 补充工作平台专用企业微信上线清单。

### Wave 3：台账/记录类模块全量落地

- 总经办培训、会议、安全月活动、年度工作计划。
- 船务部培训、演练、值守、岸基叫应、会议记录、案例学习。
- 业务部签船记录表、船舶动态记录表。
- 重点是高保真表单、资料留存和打印归档。

### Wave 4：作业闭环类模块全量落地

- 业务部作业人员签到台、接收工作组流程、围油栏、垃圾/污油水/生活污水接收。
- 中船工作组和平陆运河工作组五步作业闭环。
- 重点是步骤流转、现场图片、签认和完工确认。

### Wave 5：检查整改类模块全量落地

- 总经办安全隐患排查管理。
- 船务部船舶自查排查、船舶检验、密闭空间、污油水接收作业、海事安检系统。
- 重点是检查项、整改闭环、整改前后照片与 A4 打印。

### Wave 6：考勤统计类模块全量落地

- 财务部统计中心。
- 船务部船员考勤。
- 作业签到数据与工作组考勤数据纳入统一统计口径。

### Wave 7：资产服务类 + 审批类模块全量落地

- 后勤部仓库、办公室、食堂、宿舍、车辆维修保养。
- 船务部设备保养、燃油加注、航次计划审批。
- 审批类业务统一走企业微信原生审批。

### Wave 8：全平台联调、验收、上线准备

- 完成跨模块权限、消息联动、打印归档、统计口径统一验收。
- 完成企业微信正式上线前检查与真机回归。
- 输出 M4 验收归档与 M5 优化项清单。
