# 里程碑 5 需求文档：上线强化与遗留收口

## 1. 文档定位

本文件定义里程碑 5 的目标、范围边界、企业微信上线口径和遗留模块处理策略，用于指导 M5 的 SDD 补充、开发排期、联调验证与正式上线材料准备。

M5 不再以新增大业务模块为主线，而是承接 M4 已完成的全量工作平台，实现从“规格与样例实现可运行”到“可持久化、可排障、可留痕、可上线”的收口。

## 2. 里程碑目标

### 2.1 主目标

- 完成工作平台底座正式化，摆脱内存态运行方式。
- 完成企业微信上线强化，补齐审批桥、真机回归、告警和留痕能力。
- 固化统计导出、对账、打印一致性和关键链路可观测性。
- 将 `财务板块`、`海图更新` 两个遗留模块纳入 M5 文档与 SDD 边界，但不作为首批开发目标。

### 2.2 成功标准

- 工作平台记录、步骤、附件、打印快照、审批实例镜像均有持久化规格。
- 审批异常实例支持检索、重试、对账和管理员诊断。
- 企业微信 iOS / Android 真机回归有明确执行清单和证据留存模板。
- 统计导出、财务口径对账和打印模板标准化具备可执行规格。
- 遗留模块不再停留在原始需求散点，至少形成最小可执行 SDD 边界。

## 3. 范围说明

### 3.1 纳入范围

#### 工作平台底座正式化

- 工作平台运行时实体、迁移、索引与关系约束。
- 记录列表、详情、动作、附件、打印快照的持久化型 API 契约。
- 审批模板绑定、审批实例镜像、回调审计、异常重试、对账补偿。
- 工作平台自动化测试基线与上线检查材料结构。

#### 企业微信上线强化

- 审批回调验签/解密、幂等、重放保护、失败告警和管理员检索。
- OAuth2、JS-SDK、审批桥、消息推送的专项检查清单。
- iOS / Android 企业微信真机回归场景、截图/录屏留痕与缺陷闭环模板。

#### 数据正确性与交付一致性

- 月度考勤统计导出接口与导出口径冻结。
- 财务对账接口与校验口径冻结。
- 打印模板标准化与归档快照规范。
- 可观测性与 SLI/SLO 指标需求冻结。

#### 遗留模块收口

- `财务板块`：仅冻结业务边界、角色、输入输出方向和待确认清单，不冻结字段级 API。
- `海图更新`：冻结为 `ledger_form` 模板的最小规格，字段范围限定为更新批次、适用船舶、版本/日期、说明、附件、确认记录。

### 3.2 不在 M5 首批开发范围

- 再新增一轮工作平台大业务模块。
- 重写 M1-M4 历史需求文档、验收归档或架构总览。
- 为 `财务板块` 发明未在原始资料出现的字段、流程或报表。
- 对外部系统 SSO、复杂预算体系、BI 大屏做前置设计。

## 4. 关键决策

### 4.1 工作平台运行时必须正式落库

M4 已完成模块矩阵、页面壳层和接口骨架，但工作平台当前运行态仍偏样例型。M5 必须将以下对象正式化：

- `BusinessRecord`
- `BusinessStep`
- `BusinessAttachment`
- `BusinessActionLog`
- `BusinessPrintSnapshot`
- `WecomApprovalTemplateBinding`
- `WecomApprovalInstanceSync`

### 4.2 审批真源继续遵循企业微信单真源原则

- 审批类业务最终结果仍以企业微信审批实例为真源。
- 系统内只保留业务上下文、镜像状态、同步审计、异常诊断与检索数据。
- M5 强化的是桥接能力和运维能力，不引入双真源。

### 4.3 遗留模块处理策略

- `财务板块`：纳入 M5 目录，但只做到“边界冻结 + 待确认清单”，后续是否单独立项由业务确认决定。
- `海图更新`：纳入 M5 模块矩阵与 UI/DB 边界，开发排在工作平台主线之后。

## 5. 企业微信约束

M5 必须继续遵循企业微信官方开发文档，并将以下事项转化为实施型规格：

- 网页授权：<https://developer.work.weixin.qq.com/document/path/91335>
- 构造网页授权链接：<https://developer.work.weixin.qq.com/document/path/91022>
- 获取访问用户身份：<https://developer.work.weixin.qq.com/document/path/91023>
- 获取 `access_token`：<https://developer.work.weixin.qq.com/document/path/91039>
- 回调配置：<https://developer.work.weixin.qq.com/document/path/90930>
- 发送应用消息：<https://developer.work.weixin.qq.com/document/path/90236>
- JS-SDK 开始使用：<https://developer.work.weixin.qq.com/document/path/90514>
- JS-SDK 签名算法：<https://developer.work.weixin.qq.com/document/path/90539>
- 审批流程引擎：<https://developer.work.weixin.qq.com/document/path/90269>
- 获取审批模板详情：<https://developer.work.weixin.qq.com/document/path/91982>
- 获取审批申请详情：<https://developer.work.weixin.qq.com/document/path/91983>

冻结前提如下：

- H5 页面仅在企业微信可信域名下运行。
- OAuth2、JS-SDK、消息推送和审批回调的生产配置需形成检查清单与留痕模板。
- 审批回调必须具备验签、幂等和重放保护能力。
- 真机联调必须覆盖企业微信 iOS 与 Android 容器，并形成截图或录屏证据。

## 6. Wave 规划

### Wave 1：M5 文档冻结

- 新增 M5 需求文档与执行计划。
- 新增工作平台运行时存储规格、审批运维规格、真机回归留痕模板。
- 更新工作平台 README、优化 backlog、模块矩阵、状态/UI 规格。
- 将 `财务板块`、`海图更新` 纳入 M5 文档边界，标记为“规格纳入，开发后置”。

### Wave 2：工作平台底座正式化

- 用 TypeORM + PostgreSQL 落地工作平台运行时实体与迁移。
- 替换 `WorkbenchService` 的内存记录/审批实例存储方式。
- 建立工作平台集成测试基线。
- 推荐优先开发项：`WS-2A 工作平台运行时持久化与审批实例落库`。

### Wave 3：企业微信审批桥强化与上线留痕

- 补齐审批回调验签/解密、幂等、重放保护、重试与告警规格。
- 增加管理员检索、重试、对账诊断接口。
- 输出真机回归报告模板与缺陷闭环模板。
- 同步补权限矩阵自动化校验要求。

### Wave 4：数据正确性与交付一致性

- 固化考勤导出、财务对账、打印模板标准化。
- 补齐关键链路可观测性、指标与告警面板需求。
- 完成 `财务板块`、`海图更新` 的最小可执行 SDD；如资料仍不足，只冻结边界与待确认清单。

## 7. 验收要求

1. 工作平台不再依赖内存态保存记录和审批实例。
2. 审批异常实例可检索、可重试、可对账、可审计。
3. 统计导出、财务对账、打印快照三者口径一致。
4. 权限显示、消息提醒、审批状态三者一致。
5. 企业微信 iOS / Android 真机回归有留痕证据，可直接作为上线材料。
6. `财务板块`、`海图更新` 均进入 SDD 目录并有清晰边界说明。
