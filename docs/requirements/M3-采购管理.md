# 里程碑 3 需求文档："采购管理"模块

## 文档定位

本文档用于明确里程碑 3 的业务目标、范围边界和关键架构决策，供 Codex 后续在 `docs/specs/procurement/` 下编写详细规格。

本文档不包含具体 API、数据库字段级定义、页面交互细节或状态管理设计；这些内容应在采购模块 spec 中补齐。

## 目标

交付覆盖 5 个部门的采购录单、审批、统计和打印系统，支持日常采购申请闭环、部门细分查询和月度/年度经营分析。

## 核心功能清单

| 功能 | 说明 |
|---|---|
| 采购录单 | 创建采购申请单，录入部门、细分对象、金额、摘要、附件等信息 |
| 审批流程 | 采用录单模式：员工发起，部门主管审核，总经办终审 |
| 月度/年度采购报表 | 提供按部门聚合的统计视图，并支持年度趋势查看 |
| 部门采购清单 | 查询某部门全部采购明细 |
| 部门细分采购清单 | 船舶部按船舶查看，后勤部按子类别查看 |
| A4 打印导出 | 将采购单和报表导出为适合 A4 打印的 PDF |
| 附件上传与留存 | 支持上传采购相关附件并长期关联留存 |
| 3 年内历史查询 | 支持查询近 3 年采购单据和报表数据 |
| 年度采购预算 | 按年度、部门和采购分类维护预算，并统计终审通过采购单的执行金额 |

## 部门结构

| 部门 | 标识 | 采购范围 | 细分维度 |
|---|---|---|---|
| 总经办 | `general_office` | 大额采购、业务支出 | 无 |
| 业务部 | `business_dept` | 业务部单据 | 无 |
| 财务部 | `finance_dept` | 所有开支单 | 无 |
| 船舶部 | `shipping_dept` | 船舶/船务单据 | 按船舶（苏南012 / 苏南022 / 辅2-16） |
| 后勤部 | `logistics_dept` | 办公 / 仓库 / 宿舍 / 食堂 / 车辆 / 杂项 | 按子类别 |

约束说明：

- 细分维度仅适用于船舶部和后勤部。
- 其余部门录单时不要求额外细分对象。
- 船舶名称与后勤子类别的最终枚举，应在后续 spec 中结合种子数据和业务确认固化。

## 核心实体模型（概念级）

### `procurement_orders`

采购申请单主实体，至少承载以下概念信息：

- 所属部门
- 细分对象（可空，仅船舶部/后勤部使用）
- 申请金额，使用 `NUMERIC(12,2)`
- 采购摘要 / 事由说明
- 当前审批状态
- 申请人、申请时间
- 审计字段与软删除标记

### `procurement_approvals`

审批记录实体，至少承载以下概念信息：

- 关联采购申请单
- 审批人
- 审批动作
- 审批意见
- 审批时间

### 报表

报表仅为聚合查询结果，不单独建立实体表，不做物化表作为本阶段默认方案。

### `procurement_budgets`

年度采购预算实体，按“年度 + 部门 + 采购分类”唯一维护。船务部复用船舶字典，
后勤部复用后勤分类字典，其他部门统一使用“未细分”。预算调整必须记录原因和
不可变审计轨迹。

## 审批工作流

采购管理采用录单审批模式：

1. 员工发起采购申请并保存草稿或提交。
2. 部门主管审核，决定通过、退回或驳回。
3. 总经办进行终审，决定通过、退回或驳回。

状态机定义：

`draft -> submitted -> dept_approved -> final_approved`

异常分支：

- 任一审批节点可将单据退回修改。
- 被明确否决的单据进入 `rejected` 状态。

本阶段统一状态集合：

- `draft`
- `submitted`
- `dept_approved`
- `final_approved`
- `rejected`

权限要求：

- 认证与基础 RBAC 复用 `docs/specs/common/auth-spec.md`
- 新增权限点：
  - `procurement_submit`
  - `procurement_approve`
  - `procurement_report`

## 报表需求

需支持以下报表或统计视图：

| 报表 | 说明 |
|---|---|
| 月度采购数据表 | 按部门 + 月份聚合金额、单据数 |
| 年度采购数据表 | 按部门 + 年度聚合，并展示月度趋势 |
| 部门采购清单 | 部门维度下的全部采购明细 |
| 部门细分采购清单 | 船舶部按船舶，后勤部按子类别查看 |

设计原则：

- 统计口径以已提交及进入审批流的单据为基础，具体是否包含 `rejected` 数据在报表 spec 中明确。
- 报表查询需支持时间范围、部门、细分对象等筛选。
- 报表导出与在线查看应共享同一统计口径。

## 年度预算需求

- 预算按年度、部门和采购分类配置。
- 已执行金额仅统计 `final_approved` 且 `expense_date` 属于目标年度的采购单。
- `expense_date` 为空的采购单不计入预算执行。
- 预算和已执行金额均大于 `0` 时，采购首页才展示预算卡片。
- 超预算显示真实执行率、风险色和超出金额。
- 仅 `system_admin`、`general_office` 可维护预算，所有已认证用户可查看汇总。
- 预算可调整和停用，不允许硬删除；所有调整必须记录操作人、时间、前后值和备注。

## 从 M1 复用的模式

### 直接复用

- 文件上传的 OSS presign 模式
- 审计字段
- 软删除
- UUID 主键
- API 信封格式
- 分页约定
- JWT 认证

### 需要扩展

- OSS bucket 目录新增 `procurement/`
- RBAC 增加采购相关权限点
- PDF / A4 生成功能作为新增能力接入

PDF 生成建议优先评估：

- `puppeteer`
- `@react-pdf/renderer`

最终技术选型由详细 spec 和实现阶段结合部署环境决定。

## 3 年查询与打印要求

- 默认支持近 3 年历史采购单据与报表查询。
- 时间范围筛选需支持按月份、按年度及自定义起止日期。
- 打印输出需适配 A4 纸张，保证中文、金额、表格列宽和分页可读。
- 采购单打印与报表打印应分别提供模板，不强行复用同一版式。
- 打印结果默认为 PDF 文件，是否支持浏览器直接打印由前端实现方案决定。

## 前置依赖

1. M1 认证、文件上传、基础审计能力保持可复用。
2. 角色与组织信息可支撑部门主管、总经办等审批身份识别。
3. PostgreSQL、OSS、前端打印能力可用。
4. 采购部门、船舶与后勤子类别基础字典在 spec 阶段完成确认。

## 不在范围

- 企业微信原生审批流打通
- 预算预占、冻结、额度扣减、释放或预算对账
- 供应商管理主数据
- 发票识别、报销系统集成
- 3 年以前历史数据治理

## 验收标准

1. 5 个部门均可建立采购申请，并符合各自的细分维度规则。
2. 采购申请可按 `draft`、`submitted`、`dept_approved`、`final_approved`、`rejected` 状态稳定流转。
3. 审批链路满足“员工 -> 部门主管 -> 总经办”的录单模式，且支持退回修改。
4. 系统可生成月度、年度、部门明细、部门细分明细四类统计视图。
5. 采购单与报表均可导出为适合 A4 打印的 PDF。
6. 单据附件可上传、绑定并留存，历史数据支持近 3 年查询。
7. 年度预算可按部门和采购分类维护，执行金额口径正确，调整过程可审计。
