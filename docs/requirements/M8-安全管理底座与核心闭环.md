# 里程碑 8 需求文档：安全管理底座与核心闭环

## 1. 文档定位

M8 承接 M1-M6 已上线的企业微信 H5、工作平台、文件、采购和审批能力，解决当前平台在数据权限、流程执行、现场证据、计划任务和检查整改方面的基础缺口。

M8 的目标不是一次性新增所有航运安全业务，而是建立后续专业安全模块必须共用的可信底座，并首先打通“计划任务”和“检查问题 CAPA”两条核心闭环。

## 2. 里程碑目标

### 2.1 主目标

- 建立安全领域规格入口、术语和边界。
- 将工作平台权限从模块角色扩展为角色加船舶、本人、任务参与人和状态属性。
- 增强通用流程的执行人、审核人、多人并行、退回、终止、作废和审计能力。
- 建成统一附件、现场拍照、电子签名、定位证据、打印下载和异步导出。
- 建成船舶、人员、任职、设备和证书安全主数据基础。
- 建成计划任务、统一待办、任务日历、催办和任务转移。
- 建成检查、隐患、不符合项、原因分析、纠正预防措施和验证关闭。

### 2.2 成功标准

1. 船员默认只能访问本人、本船或本人参与的记录。
2. 每个步骤只有授权执行人可以操作，审核人与整改责任人按规则隔离。
3. 所有工作平台记录均可使用统一附件上传、预览和下载。
4. 打印和导出生成真实文件，并继承记录权限。
5. 年度或周期计划可生成任务，并进入真实待办和日历。
6. 检查发现可按规则生成问题或不符合项。
7. 每个问题具备来源、等级、责任人、期限、措施、证据、验证和关闭轨迹。
8. 企业微信消息可深链到具体任务，但不改变企业微信审批单真源原则。

## 3. 范围说明

### 3.1 纳入范围

#### 权限与流程底座

- ABAC 数据范围：部门、船舶、本人、任务参与人、记录状态。
- 步骤执行人、协作人、审核人和观察人。
- 多人并行规则：全部完成、任一完成、达到人数。
- 退回指定步骤、终止、作废、重开、代理和任务转移。
- 所有动作审计及管理员敏感数据访问审计。

#### 证据与归档

- 通用文件选择、企业微信拍照、上传进度、预览和删除。
- 签名证据：签名图、签署人、签署时间、业务摘要哈希。
- 定位证据：经纬度、精度、采集时间、业务场景和人工异常说明。
- PDF 快照下载、版本、水印和生成日志。
- 异步导出任务、进度、结果文件和失败重试。

#### 安全主数据

- 船舶安全档案及与证书、人员、设备的关系。
- 人员基础档案、企业微信身份和船舶任职关系。
- 设备基础档案、所属船舶、设备分类和状态。
- 人员、船舶和设备证书统一关联。
- 主数据导入、重复校验、停用和历史引用保护。

#### 计划任务与统一待办

- 年度、月度、周期和单次计划。
- 计划项自动生成任务。
- 任务负责人、参与人、计划时间、期限和完成条件。
- 统一待办、我发起的、我参与的、已完成和逾期。
- 任务日历、催办、升级、改期、取消和任务转移。
- 企业微信应用消息深链。

#### 检查问题与 CAPA

- 法规、公司和船舶检查模板。
- 检查计划、任务、项目结果、照片和多人签认。
- 隐患、不符合项和一般问题的统一问题模型。
- 重大性判定、逾期升级和人工上报留痕。
- 根因分析、纠正措施、预防措施、责任人和期限。
- 完成证据、验证、有效性评价、返工和关闭。
- 现有安全隐患、自查、检验和海事安检记录的迁移或来源关联。

### 3.2 不在 M8 范围

- 船员招聘、调配、健康、考试和熟悉职责完整业务。
- 明火、危险货物、高空舷外等专业作业许可。
- 应急事件、事故调查、防台全过程。
- 设备年度/月度维护、修理和备件库存完整闭环。
- 受控文件、内审和管理评审完整闭环。
- 海事监管、AIS、CCTV 等外部接口。
- 独立微信小程序。

## 4. 关键决策

### 4.1 不推翻现有工作平台

现有模块和记录继续保留。M8 通过公共任务、权限、证据和问题服务增强既有模块，必要时为专业流程增加聚合页面。

### 4.2 权限必须在后端强制执行

前端隐藏按钮不构成权限控制。记录查询、详情、动作、附件、导出和打印均必须执行相同数据范围检查。

### 4.3 问题与 CAPA 使用独立领域对象

问题、措施和验证不得只存放在工作平台记录 `payload` 或摘要文本中。通用记录可作为来源，但问题闭环必须具备结构化实体和关联。

### 4.4 任务是统一执行入口

计划、检查、整改、验证和后续 M9 业务都应生成统一任务。企业微信审批仍可作为审批真源，但系统任务负责业务上下文、执行状态和待办聚合。

### 4.5 证据不可静默替换

签名、定位、照片和归档 PDF 的新增、删除或替换必须留痕。已用于关闭或归档的证据不得无审计覆盖。

## 5. 企业微信与移动端约束

- 保持企业微信 H5，不建设小程序。
- 支持工作台和应用消息直达目标任务。
- 拍照和定位优先使用企业微信 JS-SDK，失败时提供可理解的人工补充路径。
- 签名使用 H5 签名板，保存签名证据和摘要哈希。
- 弱网时允许保存本地草稿，但服务端幂等键必须防止重复提交。
- 定位不是所有任务的强制条件，由任务或模板规格声明。

## 6. Wave 规划

### Wave 1：M8 文档、架构与规格基线

- 冻结术语、领域边界、路由、权限模型和迁移原则。
- 建立 `docs/specs/safety/` 入口及 API/DB/state/UI 规格清单。
- 建立 M8 差距基线、任务编号、验收模板和提示词。

### Wave 2：数据权限与流程状态链

- 落地 ABAC 数据范围。
- 落地步骤参与人、多方完成规则和动作授权。
- 补齐退回、终止、作废、重开、代理和审计。

### Wave 3：统一证据、打印、导出与移动能力

- 统一附件和企业微信拍照。
- 落地签名、定位和证据审计。
- 完成 PDF 下载、水印和异步导出。

### Wave 4：安全主数据中心

- 建成船舶、人员任职、设备和证书关联档案。
- 提供选择器、导入、停用和重复校验。
- 迁移通用表单中的关键文本引用。

### Wave 5：计划任务、统一待办与日历

- 建成计划、计划项和执行任务。
- 建成待办、日历、催办、升级、改期、取消和转移。
- 接入企业微信应用消息深链。

### Wave 6：检查、问题与 CAPA

- 建成检查模板、计划、任务和多人检查。
- 建成问题、不符合项、根因、措施、验证和有效性评价。
- 接入既有隐患、自查、检验和海事安检来源。

### Wave 7：数据迁移、联调、验收与上线

- 迁移存量数据并保留来源。
- 完成全链路测试、性能、弱网和真机回归。
- 形成发布、回滚、验收和 Hypercare 材料。

## 7. 验收要求

1. 每个 Wave 均有独立验收文档和证据索引。
2. OpenAPI、数据库、状态和 UI 规格与代码一致。
3. 权限测试至少覆盖系统管理员、部门角色、船长和普通船员。
4. 集成测试使用迁移驱动的 PostgreSQL testcontainers。
5. 跨模块自动创建使用幂等键，并可重试、对账和人工修复。
6. 前端覆盖加载、空态、错误、权限不足、弱网和重复提交。
7. 工作平台看板和日历不得继续使用无来源静态业务数据。
8. M8 结束时，检查问题 CAPA 主链路可在企业微信真机完成。
