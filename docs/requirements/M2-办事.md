# 里程碑 2 需求文档: "办事"模块

## 文档定位

本文档用于明确里程碑 2 的业务目标、范围边界、角色权限和上线约束，供后续在 `docs/specs/office/` 下编写详细规格，并指导 M2 实现与测试。

本文档不展开字段级 API、数据库表结构和页面交互细节；这些内容以下沉到 office 模块 SDD 规格文档为准。

## 目标

交付企业微信工作台内可用的“办事”统一入口门户，集中承载 7 类办公端口，支持员工搜索与访问，并支持按分类分部门维护、发布和停用。

## 核心功能清单

| 功能 | 说明 |
|---|---|
| 分类目录 | 固定展示海事、海关、边检、船检、环保、其他、石化园区 7 类办事端口 |
| 搜索与筛选 | 支持按标题、摘要关键词搜索，并按分类筛选 |
| 入口访问 | 支持从企业微信 H5 内打开站内或外部端口 |
| 分类分权维护 | 按分类授予维护权限，不做动态配置 |
| 发布治理 | 端口支持草稿、发布、停用三态管理 |
| 操作审计 | 记录入口维护动作和打开动作 |

## 分类与维护权矩阵

| 分类 | code | 默认维护角色 |
|---|---|---|
| 海事 | `maritime` | `shipping`、`general_office` |
| 海关 | `customs` | `business`、`general_office` |
| 边检 | `border_inspection` | `business`、`shipping`、`general_office` |
| 船检 | `vessel_inspection` | `shipping`、`general_office` |
| 环保 | `environment` | `logistics`、`shipping`、`general_office` |
| 其他 | `other` | `general_office`、`system_admin` |
| 石化园区 | `petrochemical_park` | `business`、`general_office` |

规则说明：

- 普通登录用户仅可查看“已发布且自己有权限”的办事入口。
- 分类维护人仅可维护自己负责分类下的入口。
- `system_admin` 可跨分类查看和维护全部入口。
- 分类不开放前台新增、删除和重命名。

## 核心实体模型（概念级）

### `office_categories`

承载固定办事分类字典，包含：

- 分类编码
- 分类名称
- 排序号
- 启用状态

### `office_entries`

承载办事入口主数据，至少包含：

- 所属分类
- 标题、摘要、图标类型
- 跳转目标类型与目标值
- 打开方式
- 可见角色集合
- 管理角色集合
- 排序号
- 状态
- 审计字段与软删除

### `office_entry_audits`

记录入口治理和访问审计，至少包含：

- 关联入口
- 动作类型
- 操作人
- 快照数据
- 时间戳

## 状态机

`draft -> published -> disabled`

规则说明：

- 新建入口默认进入 `draft`。
- `draft` 可编辑、发布。
- `published` 可编辑、停用。
- `disabled` 可继续编辑并再次发布。
- 删除不作为 M2 对外能力，默认采用停用与软删除组合治理。

## API 与前端能力边界

需支持的最小接口集合：

- `GET /api/v1/office/categories`
- `GET /api/v1/office/entries`
- `GET /api/v1/office/entries/:id`
- `POST /api/v1/office/entries/:id/open`
- `GET /api/v1/office/admin/entries`
- `POST /api/v1/office/admin/entries`
- `PATCH /api/v1/office/admin/entries/:id`
- `POST /api/v1/office/admin/entries/:id/publish`
- `POST /api/v1/office/admin/entries/:id/disable`

前端页面范围：

- `/office` 办事首页
- `/office/search` 搜索页
- `/office/admin` 分类维护台

## 企业微信上线约束

- 系统以企业微信自建应用工作台入口交付。
- 工作台主页地址、可信域名、OAuth2 回调域名、JS 接口安全域名必须登记为正式 HTTPS 域名。
- H5 认证继续复用 OAuth2 + JWT。
- JS-SDK 签名继续沿用 iOS 首次加载 URL 规则。
- 外部端口默认按“可在企业微信内直接访问的 H5 地址”配置，不将单点登录改造作为 M2 前置。

## 从 M1 复用的模式

### 直接复用

- OAuth2 + JWT 认证
- 角色推断与 RBAC
- TypeORM migration + seed
- API 统一响应格式
- 软删除与审计字段
- React SPA 壳层与 RTK Query
- 企业微信 JS-SDK 底座

### 需要扩展

- 壳层导航从单模块扩展为多模块导航
- 新增 office 领域的实体、接口、状态与页面
- 增加端口打开与治理审计

## Phase5 扩展与收敛（新增）

用于将 M2 的核心能力做成“可上线、可验收、可追踪”的收敛阶段，范围仅覆盖以下三项扩展闭环：

1. 壳层导航从单模块扩展为多模块导航
2. 新增 office 领域的实体、接口、状态与页面
3. 增加端口打开与治理审计

对应落地要求：

- 路由与导航：`/my`、`/office`、`/procurement`、`/workbench` 统一纳入壳层模块导航。
- office 领域：实体（`office_categories`、`office_entries`、`office_entry_audits`）、接口、前端状态与页面规格保持一致。
- 审计能力：`open/create/update/publish/disable` 均可被记录并在治理台查询。

对应文档：

- 执行计划：`docs/execplans.md`（Wave5）
- 规格总览：`docs/specs/office/README.md`
- API 规格：`docs/specs/office/api/*.yaml`
- UI 与状态规格：`docs/specs/office/ui/*`、`docs/specs/office/state/*`

## 不在范围

- 收藏与最近使用
- 统一待办聚合
- 企业微信原生审批打通
- 外部系统 SSO 改造
- 复杂运营统计面板

## 验收标准

1. 登录用户可在 `/office` 查看自己有权限的已发布办事入口。
2. 支持按关键词搜索标题和摘要，并按分类筛选。
3. 站内端口和外部端口均可通过统一打开链路访问。
4. 分类维护人仅可管理自己负责分类下的入口。
5. 未发布和已停用入口不会出现在普通用户目录中。
6. 创建、更新、发布、停用、打开操作均可追踪审计。
7. 企业微信正式域名与相关后台配置具备上线检查单。
8. 壳层模块导航支持在 `my/office/procurement/workbench` 之间切换并保持当前模块高亮。
