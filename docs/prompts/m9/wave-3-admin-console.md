# M9 Wave 3 提示词：管理后台与全业务权限整合

> 状态：已规划、实施未开始。仅在用户要求执行本 Wave 时进入实施；阅读本提示词不代表本轮重新规划已经执行了功能。

## 目标与前置

交付可用的用户管理页面，让权限调整在界面、业务范围、候选人和收件人处一致生效。

W2 后端与有效授权服务已通过必要验证；读取 W1 权限矩阵。

## 必须读取

- `AGENTS.md`
- `docs/requirements/M9-平台管理与配置升级.md`
- `docs/plans/M9-execplans.md`
- `docs/plans/M9-wave-backlog.md`
- 当前Wave涉及的认证、通知、企业微信契约与实际源码；后序Wave还应读取前置验收记录。

## 本 Wave 工作

1. 执行 M9-W3A：在已有系统设置内添加用户管理，完成全部状态分页/筛选/详情、来源与生效对照、编辑预览/原因、恢复跟随、停用恢复、同步结果和历史。
2. 执行 M9-W3B：页面恢复/聚焦、权限类403、本人变更后刷新当前身份与相关业务缓存，账号不可用时清会话，防止无限刷新。
3. 执行 M9-W3C：统一采购审批/收件人、自查候选人、证件提醒、企业资料制度、任务/学习选择器等身份来源；移除旁路额外授予。
4. 执行 M9-W3D：完成桌面与H5流程、加载/空态/错误/冲突恢复；env管理员资格与主应用配置来源只读。

## 固定约束

- 系统管理员唯一来源为env；主应用、OAuth、回调与安全参数仍由env维护，不开放后台改写。
- 全部用户含未登录通讯录成员，范围受限须明示；来源同步不覆盖人工授权，不把名单缺失当作离职。
- 人工角色替换自动业务角色，env管理员独立；保持各模块既有角色/部门/参与关系组合并明确收敛差异。
- 通知无覆盖使用主应用，错误覆盖不自动改主应用；不把env Secret复制入库。
- 不恢复原专业安全M9，不硬删除用户，不写回企业微信组织，不自动生产部署。

## 验证重点

- 浏览器验证同步未登录成员、人工调整部门角色、重新授权、旧会话与恢复跟随的完整流程。
- 用真实业务请求验证部门角色不一致、空业务角色、多部门、crew提醒差异和既有跨部门能力；不能只测菜单隐藏。
- 历史单据快照不改写，任务/船舶关系不自动转移；受限目录显示范围，未验证完整性不能标全目录通过。

按改动运行必要测试，避免复刻实现的低价值测试。所有新增/删除文档运行inventory生成和索引校验，并执行 `git diff --check`。
