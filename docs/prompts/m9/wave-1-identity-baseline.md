## 本 Wave 工作

1. 执行 M9-W1A：追踪 OAuth/JWT/me/刷新、env 管理员与采购/提醒/自查等旁路；确定唯一有效身份服务及模块权限矩阵。
2. 执行 M9-W1B：冻结来源/人工部门与角色、平台状态、授权版本、来源乱序、管理员管理 API 和全目录同步契约；明确全企业覆盖验收前置。
3. 执行 M9-W1C：冻结推送配置白名单、主应用缺省、加密/缓存/版本/重试规则和增量迁移、兼容回滚。
4. 核对人工财务部门+shipping角色、空角色、旧职位、env管理员提升/撤销与既有disabled组合；登录角色兼容和旁路权限收敛分开记录。

## 固定约束

- 系统管理员唯一来源为env；主应用、OAuth、回调与安全参数仍由env维护，不开放后台改写。
- 全部用户含未登录通讯录成员，范围受限须明示；来源同步不覆盖人工授权，不把名单缺失当作离职。
- 人工角色替换自动业务角色，env管理员独立；保持各模块既有角色/部门/参与关系组合并明确收敛差异。
- 通知无覆盖使用主应用，错误覆盖不自动改主应用；不把env Secret复制入库。
- 不恢复原专业安全M9，不硬删除用户，不写回企业微信组织，不自动生产部署。

- 记录数据质量、通讯录权限和主应用可见范围的真实未知项，不以推测代替证据。
