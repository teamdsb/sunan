# M9 Wave 4 提示词：后台推送配置与消息整合

> 状态：已规划、实施未开始。仅在用户要求执行本 Wave 时进入实施；阅读本提示词不代表本轮重新规划已经执行了功能。

## 目标与前置

支持后台填写可选同企业通知应用，默认使用主应用，并保持凭据、缓存和投递一致。

W1 已冻结配置契约；配置后端可与W2并行，最终收件人接入依赖W2/W3有效身份。

## 本 Wave 工作

1. 执行 M9-W4A：配置整组原子保存、乐观锁版本、认证加密与独立env主密钥；API和日志审计不暴露Secret。
2. 执行 M9-W4B：无覆盖使用完整env主应用，半配置拒绝，错误覆盖/读取失败不静默回退；token与锁按企业/应用/配置版本隔离。
3. 执行 M9-W4C：证书/采购/任务通知统一解析，发送前核验有效收件人；记录实际应用/版本/来源、失败重试及结果不确定的人工核对。
4. 执行 M9-W4D：系统设置中增加推送页，支持保留已存Secret、AgentID变更重填、定向草稿测试、保存和明确清除覆盖。

## 固定约束

- 系统管理员唯一来源为env；主应用、OAuth、回调与安全参数仍由env维护，不开放后台改写。
- 全部用户含未登录通讯录成员，范围受限须明示；来源同步不覆盖人工授权，不把名单缺失当作离职。
- 人工角色替换自动业务角色，env管理员独立；保持各模块既有角色/部门/参与关系组合并明确收敛差异。
- 通知无覆盖使用主应用，错误覆盖不自动改主应用；不把env Secret复制入库。
- 不恢复原专业安全M9，不硬删除用户，不写回企业微信组织，不自动生产部署。

## 验证重点

- 验证C1-C4：默认、半配置、保留/清除、密钥缺失/解密错误、配置读取失败、缓存隔离、并发/多实例/轮换。
- 连接验证不能代替真实送达；草稿测试只发选定测试人且不改线上配置；主应用OAuth/通讯录/SDK/回调不受影响。
- 沿用原业务去重键，成功不重推；结果不确定不得自动跨应用重试；配置恢复创建递增版本。

按改动运行必要测试，避免复刻实现的低价值测试。所有新增/删除文档运行inventory生成和索引校验，并执行 `git diff --check`。
