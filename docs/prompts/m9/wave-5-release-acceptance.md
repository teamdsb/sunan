## 本 Wave 工作

1. 执行 M9-W5A：使用脱敏/合成存量演练角色基线、旁路收敛、UUID/外键、覆盖/停用、密钥恢复和兼容回滚。
2. 兼容版本同时支持新授权和通知配置/加密/投递规则；否则暂停访问及推送入口/worker，不直接用忽略人工设置的旧程序。
3. 执行 M9-W5B：核对U1-U9、C1-C4、R1，运行必要自动化、完整质量门禁与浏览器链路；建立真实全目录、独立应用、iOS/Android/桌面的现场矩阵。
4. 执行 M9-W5C：只按实际实现更新操作手册/截图清单、env示例、企业微信配置矩阵和发布/回滚说明，归档各Wave证据与遗留项。

## 固定约束

- 系统管理员唯一来源为env；主应用、OAuth、回调与安全参数仍由env维护，不开放后台改写。
- 全部用户含未登录通讯录成员，范围受限须明示；来源同步不覆盖人工授权，不把名单缺失当作离职。
- 人工角色替换自动业务角色，env管理员独立；保持各模块既有角色/部门/参与关系组合并明确收敛差异。
- 通知无覆盖使用主应用，错误覆盖不自动改主应用；不把env Secret复制入库。
- 不恢复原专业安全M9，不硬删除用户，不写回企业微信组织，不自动生产部署。

## 验证重点

- 按当前package scripts执行API lint、unit/integration、Web test、API/Web build，变更的OpenAPI逐一校验；保留真实命令和结果。
- 全目录验收要求主应用读取并核对全企业目标成员；局部或未验证不计全量通过。真实送达、三端、生产演练未执行须明确记录。
- 检查回滚不恢复已撤业务权限、不忽略独立通知覆盖、不复用旧配置版本；结果不确定有人工处理，成功消息不重发。

按改动运行必要测试，避免复刻实现的低价值测试。所有新增/删除文档运行inventory生成和索引校验，并执行 `git diff --check`。
