# M6 生产运维与可观测交付（Wave 4）

## 1. 文档定位

本文件用于 Wave 4 的统一交付，覆盖发布顺序、迁移顺序、回滚条件、备份恢复、告警阈值、值班职责与恢复 SOP。

## 2. 发布与迁移顺序

固定顺序：

1. PostgreSQL 备份并校验可恢复。
2. 预发布执行 migration 演练与 smoke。
3. 企业微信后台切换 rehearsal（不切生产可见范围）。
4. 生产执行 migration。
5. 发布后端。
6. 发布前端静态资源并刷新 CDN。
7. 执行生产 smoke（四大板块 + 审批回调 + 消息 + 导出 + 打印）。
8. 进入 Hypercare。

## 3. 备份与恢复要求

- PostgreSQL：发布前全量备份 + 至少 1 次恢复演练记录。
- Redis：保留关键缓存重建策略（令牌缓存可重建，不作为恢复阻塞项）。
- OSS：附件元数据与对象一致性抽检（至少抽检 20 条）。
- 恢复目标：P0 事故 30 分钟内恢复核心链路。

## 4. 关键可观测面

| 链路 | 核心日志字段 | 成功阈值 | 失败告警阈值 |
|---|---|---|---|
| OAuth2 回调 | `requestId`/`corpId`/`agentId`/`code` | 成功率 >= 99.5% | 5 分钟失败率 > 2% |
| JS-SDK 签名 | `url`/`nonceStr`/`timestamp` | 成功率 >= 99.5% | 10 分钟失败 >= 10 次 |
| 审批发起 | `moduleCode`/`recordId`/`processInstanceId` | 发起成功率 >= 99% | 10 分钟失败 >= 5 次 |
| 审批回调 | `eventId`/`processInstanceId`/`callbackVersion`/`requestIp` | 回调处理成功率 >= 99% | 5 分钟失败 >= 3 次 |
| 消息发送 | `toUser`/`msgType`/`errcode` | 成功率 >= 99% | 10 分钟失败 >= 5 次 |
| 文件回调 | `fileId`/`ossKey`/`status` | 成功率 >= 99% | 10 分钟失败 >= 5 次 |
| 导出任务 | `jobId`/`module`/`status`/`durationMs` | 30 分钟内完成率 >= 95% | 超时任务 >= 3 条 |
| 打印快照 | `recordId`/`renderedFormat` | 成功率 >= 99% | 30 分钟失败 >= 3 次 |

## 5. 告警分级

- P0：登录不可用、审批主链路中断、数据库不可用。
- P1：关键链路成功率下降但可降级运行。
- P2：局部功能异常，不阻断核心业务。

## 6. 值班职责

| 角色 | 职责 |
|---|---|
| 发布负责人 | 指挥发布窗口与决策是否回滚 |
| 后端值班 | API、回调、消息、导出、打印链路恢复 |
| 前端值班 | H5 页面可用性与 JS-SDK 问题恢复 |
| 企业微信管理员 | 后台配置核对与回切 |
| DBA | 备份、迁移、恢复执行 |
| 业务确认人 | 关键业务链路验收签字 |

## 7. 恢复 SOP

1. 识别故障等级（P0/P1/P2）。
2. 锁定影响面（我的/办事/采购/工作平台）。
3. 执行快速止损（限流、降级、回切配置）。
4. 执行修复动作（重试、回滚、恢复）。
5. 回归抽检四大板块核心链路。
6. 记录事件时间线与复盘结论。
