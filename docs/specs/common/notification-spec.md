# 通知推送规格

## 概述

系统通过企业微信应用消息推送实现主动通知。里程碑1的核心通知场景是证书到期提醒。

详细的消息推送 API 规格见 `docs/specs/wecom/message-push-spec.md`。

## 通知触发场景

| 场景 | 触发时机 | 接收对象 | 优先级 |
|---|---|---|---|
| 证书即将到期 | 每日 09:00 定时扫描 | 相关负责人 | 高 |
| 合同即将到期 | 每日 09:00 定时扫描 | 总经办成员 | 高 |

## 通知路由规则

不同类型证书/合同的通知接收人：

| 对象类型 | 通知接收人 |
|---|---|
| 船舶证书 | 船务部管理员 + 总经办 |
| 车辆证书 | 后勤部负责人 + 总经办 |
| 人员证书 | 当事人 + 所在部门管理员 |
| 人员合同 | 当事人 + 总经办 |
| 服务合同 | 总经办 |

## M8 Wave 5 任务通知

计划任务的分派、催办、转移和逾期升级使用企业微信应用消息，但消息只提醒，不改变任务、计划或审批状态。每个接收人建立独立的持久化投递记录，包含任务 ID、消息类型、去重键、负载快照、发送次数、企业微信错误、下次重试时间和最终状态。

| 场景 | 接收对象 | 去重周期 | 状态真源 |
|---|---|---|---|
| 分派或转移 | 新负责人 | 任务 + 接收人 + 分派/转移事件 | 任务与参与人关系 |
| 手工催办 | 当前负责人或有效代理 | 任务 + 接收人 + 催办业务周期 | 任务动作审计 |
| 逾期升级 | 负责人和规则指定的升级接收人 | 任务 + 接收人 + 升级级别 + 期限日 | 服务端逾期计算 |

任务投递状态为 `queued`、`dispatching`、`sent`、`failed`、`skipped` 或 `uncertain`。同一去重键已经 `sent` 或 `skipped` 时不得再次推送；失败重试沿用该键并保留尝试和错误历史。任务详情深链必须是本地安全路径；认证恢复后重新执行任务 ABAC，消息 URL 不授予权限。

## 通知去重与人工处理

证书提醒在同一证书、收件人和到期周期内复用原提醒行，统一发送键为 `certificate-reminder:{reminderId}`；跨日不创建绕过旧投递的新键。已发送或已确认的周期不重复发送，换证到期周期变化后可生成新提醒。发送结果和管理员核对不得覆盖业务已确认或已消除状态。

采购沿用业务类型、单据、审批节点/结果键，并加入 `submittedAt` 提交周期，退回重新提交可以再次通知，旧周期不能人工重发。任务沿用既有分派、转移、催办和升级键。统一发送按原业务键加收件人持久去重，成功不因更换应用重发。

## M9 Wave 4 通知配置与发送（已实现，条件验收）

契约基线见 [W1 基线](../m9-wave1-identity-configuration-baseline.md)，实现和未执行现场项见 [W4 验收](../../acceptance/M9-wave-4.md)。

- 未设置或明确清除覆盖时使用完整 env 主应用；不把 env Secret 复制入库。独立通知应用 CorpID 固定继承 env，仅 AgentID/Secret 可由 env 管理员整组保存。
- Secret 使用独立 `SYSTEM_SETTINGS_ENCRYPTION_KEY` 做 AES-256-GCM 认证加密。空白 Secret 保留原值，更换 AgentID 必须重填；半配置、读取/解密/认证失败停止本次发送，不能回退到主应用。
- 每次发送使用一个配置快照，token/刷新锁按企业、应用、配置版本隔离；草稿测试另用随机缓存标识。OAuth、通讯录、JS-SDK 和回调继续走主应用。
- 发送前按统一有效身份和本业务的角色/参与关系重新核验；采购按审批角色选择收件人，具名未来任务负责人可收到分派，已转移、失效委托或不可用成员被排除。
- 通用 `notification_delivery_attempts` 保存业务来源、收件人、实际应用、来源/版本、尝试历史及脱敏错误。`sending` 表示已领取发送权，`uncertain` 表示外部结果不确定；并发未领取者不能改写业务投递结果。
- 明确失败可复用原键重试并解析新配置；`42001` 只刷新同一快照的 token 并重试一次。网络超时、断连、5xx 等结果不确定时立即停止，不自动重发或跨应用切换。`invaliduser` 记录为失败，修复成员/应用可见范围后可人工重试。
- 管理员在设置中查询最近 100 条失败、不确定或超过 15 分钟的发送中记录；不确定记录必须先人工确认已送达/未送达，确认未送达后才允许重试。人工重试再次验证当前业务资格，不能发送过期或已撤权内容。

管理 API、密钥轮换和草稿测试约定见 [消息规格](../wecom/message-push-spec.md)。企业微信真实可见范围、真实收发与三端设备证据尚未完成，连接验证仅证明取得 token。
