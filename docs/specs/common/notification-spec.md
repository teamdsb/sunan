# 通知推送规格

## 概述

系统通过企业微信应用消息推送实现主动通知。里程碑1的核心通知场景是证书到期提醒。

详细的消息推送 API 规格见 `docs/specs/wecom/message-push-spec.md`。

## 通知触发场景

| 场景 | 触发时机 | 接收对象 | 优先级 |
|---|---|---|---|
| 证书即将到期 | 每日 09:00 定时扫描 | 相关负责人 | 高 |
| 合同即将到期 | 每日 09:00 定时扫描 | 总经办成员 | 高 |

## 通知路由规则

不同类型证书/合同的通知接收人：

| 对象类型 | 通知接收人 |
|---|---|
| 船舶证书 | 船务部管理员 + 总经办 |
| 车辆证书 | 后勤部负责人 + 总经办 |
| 人员证书 | 当事人 + 所在部门管理员 |
| 人员合同 | 当事人 + 总经办 |
| 服务合同 | 总经办 |

## M8 Wave 5 任务通知

计划任务的分派、催办、转移和逾期升级使用企业微信应用消息，但消息只提醒，不改变任务、计划或审批状态。每个接收人建立独立的持久化投递记录，包含任务 ID、消息类型、去重键、负载快照、发送次数、企业微信错误、下次重试时间和最终状态。

| 场景 | 接收对象 | 去重周期 | 状态真源 |
|---|---|---|---|
| 分派或转移 | 新负责人 | 任务 + 接收人 + 分派/转移事件 | 任务与参与人关系 |
| 手工催办 | 当前负责人或有效代理 | 任务 + 接收人 + 催办业务周期 | 任务动作审计 |
| 逾期升级 | 负责人和规则指定的升级接收人 | 任务 + 接收人 + 升级级别 + 期限日 | 服务端逾期计算 |

投递状态为 `queued`、`dispatching`、`sent`、`failed` 或 `skipped`。同一去重键已经 `sent` 或 `skipped` 时不得再次推送；失败重试沿用该键并保留尝试和错误历史。任务详情深链必须是本地安全路径；认证恢复后重新执行任务 ABAC，消息 URL 不授予权限。

## 通知去重规则

同一证书同一到期提醒周期内，如已发送且对方已确认（`status = acknowledged`），不再重复推送。如未确认，每天重复提醒。M8 任务通知按上节的持久化去重键和投递状态处理，不复用证书提醒确认状态。
