# 报表审批页规格

## 页面目标

处理独立报表审批单流程。

## 审批链

`部门主管 -> 财务部 -> 总经办`

对应状态：

- `submitted`（待部门主管）
- `dept_approved`（待财务部）
- `finance_approved`（待总经办）
- `final_approved`（完成）
- `rejected`（驳回）

## 动作

- 通过
- 退回（回草稿）
- 驳回

## 展示内容

- 业务标题：按快照周期显示“`YYYY年M月采购月报`”或“`YYYY年度采购年报`”，副标题显示报表编号、部门与快照说明。
- 状态条：当前状态、统计周期、统计部门、审批渠道；仅在存在外部审批状态时补充外部状态。
- 指标摘要：采购总额、采购单数、汇总维度数。
- 统计条件：报表类型、周期、部门和其他有效参数使用标签/值映射展示，不直接渲染 JSON。
- 汇总明细：按快照 `items` 展示维度、采购单数、采购金额，并在末尾显示总计。
- 审批进度：以“创建 -> 部门审批 -> 财务审批 -> 总经办审批”展示当前节点。
- 审批轨迹：节点、结果、审批人、审批时间、意见和来源。
- 最近一次导出记录与“预览 PDF / 导出 PDF”动作。

## 交互与空态

- 草稿态可提交；其他状态不显示提交动作。
- 驳回状态按最后一条审批记录定位部门、财务或总经办节点；退回导致实体回到草稿时，详情仍显示“已退回，待修改”及实际退回节点，不得伪装成首次创建草稿。
- “预览 PDF”在生成完成后直接打开应用内预览弹窗，不异步调用 `window.open`。
- 参数快照、汇总快照或审批记录为空时，使用业务空态文案，不显示 `{}`、`[]`、`null` 或序列化 JSON。
- 详情页在桌面端使用双栏业务摘要；`980px` 以下切为单栏，`768px` 以下操作按钮和指标卡依次堆叠。
- 查询、筛选和操作控件遵循 `docs/specs/common/frontend-experience-guidelines.md` 的 `46px` 控件基线。
