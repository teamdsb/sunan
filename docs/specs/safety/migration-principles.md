# M8 数据迁移与兼容原则

## Wave 1 冻结范围

本文件只冻结后续迁移的设计与验收规则。Wave 1 不创建生产表、TypeORM migration、实体、Controller、页面或占位接口。

## 不可变原则

1. 任何新表、索引、外键、枚举和迁移须先有已评审 DB 规格，并遵循 `docs/specs/common/db-conventions.md`。
2. 每个 schema 变更使用独立 TypeORM migration，含可执行的 `up()` 和 `down()`；生产环境禁止 `synchronize: true`。
3. 现有工作平台、采购、文件和企业微信记录为迁移来源，迁移只新增规范化关联、映射和来源追溯，不覆盖来源字段或历史审计。
4. 迁移对象必须保留 `source_domain`、`source_record_id`、迁移批次和映射状态；同一来源的重复运行不得产生重复目标记录。
5. 新旧读取并存期间，旧记录保持可读；切换后仍提供来源回链和只读兼容。
6. 回滚只撤销本批新增数据、关联或开关，不删除原始文件、原始记录或历史审计。

## 执行顺序

`规格评审 -> migration 评审 -> PostgreSQL 演练 -> 备份/前置核对 -> 执行 -> 数量/关联/状态对账 -> 只读兼容验证 -> 发布观察 -> 可回滚窗口关闭`

每批迁移必须明确来源筛选条件、目标映射、幂等键、失败记录、人工修复人和恢复策略。自动建任务、自动建问题和附件关系迁移还必须记录触发版本和请求/批次标识。

## 对账与退出条件

| 维度 | 必须核对 |
|---|---|
| 数量 | 来源数、迁移成功数、跳过数、失败数及其合计 |
| 关联 | 船舶、人员、设备、文件、来源记录和任务/问题关联可追溯 |
| 状态 | 来源状态到 M8 术语状态的映射有逐项记录；不可映射项进入人工队列 |
| 文件 | 迁移只建立关系，不移动或物理删除仍被引用的 OSS 对象 |
| 回滚 | `down()` 或批次恢复后，新旧数据仍可读取且来源不丢失 |

迁移验收必须在 PostgreSQL 环境演练，并将命令输出、对账报告、异常清单和回滚结果链接到对应 Wave 验收记录。
