# Wave 6 检查、问题与 CAPA 页面规格

## 路由与入口

安全能力继续在工作平台下按路由级懒加载呈现：`/workbench/inspection-templates`、`/workbench/inspection-plans`、`/workbench/inspections/:inspectionId`、`/workbench/issues` 与 `/workbench/issues/:issueId`。它们可由 Wave 5 任务详情、企业微信深链或现有四类工作平台记录进入；OAuth 恢复后先重新拉取资源并执行 ABAC，不显示未授权标题、人员、期限、来源或附件元数据。

不新增第五个一级导航、不预加载到无关入口。现有 `goa_safety_hazard`、`shipping_self_inspection`、`shipping_vessel_inspection`、`shipping_maritime_safety_check` 详情在后端返回已授权链接时显示“关联问题”；问题详情显示模块名称、来源记录号、检查项和返回原记录链接。

## 页面行为

| 页面 | 主要内容 | 关键动作与反馈 |
|---|---|---|
| 模板管理 | 模板来源、适用范围、已发布/草稿版本、导入来源和检查项 | 创建新版本而非编辑已发布版本；发布前显示检查项完整性和影响“仅未来任务”。 |
| 检查计划 | 模板版本、负责人、参与人、all/any/quorum、周期、期限、生成运行 | 调用生成/对账后显示 created/skipped/failed；失败提供受权重试，不删除历史任务。 |
| 移动检查表 | 固定模板版本、每项结论、说明、照片/证据、个人签名和完成进度 | 草稿自动保留表单值；提交前提示未填项；提交后该人只读；未达到门槛时显示“尚不能汇总”及人数。 |
| 问题中心 | 来源、类型、等级、船舶、责任范围、责任人、期限、逾期与 CAPA 状态 | 筛选结果可进入来源检查项和 CAPA；critical/major 用风险标签但关闭按钮只依据 `availableActions`。 |
| CAPA 详情 | 根因、纠正/预防措施、责任人/期限、完成证据、验证、返工与有效性评价 | 措施责任人只提交自己；验证抽屉拒绝本人措施；失败必须填写返工原因；关闭前展示逐项门槛清单。 |

## 移动、弱网与安全反馈

- 320px 起单列，无横向滚动；检查结论使用可点击至少 44px 的大按钮，签名、拍照和文件组件复用 Wave 3 证据组件。
- 首次加载显示业务骨架，列表无数据展示范围对应空态，失败显示可理解原因与受权重试；401 提供认证恢复，403 只显示“无权访问或执行此记录”。
- 表单提交期间禁用相同动作，并使用 Idempotency-Key；网络失败保留本地未提交值，明确区分“已保存草稿”“已签认提交”和“尚未同步”。
- 模板/检查/CAPA 修改成功后失效任务、检查、问题、统计和来源详情缓存；不以本地乐观状态绕过后端门槛。
- 统计卡、列表和详情链接使用同一受权 API 数据。每个指标点击后进入包含来源检查项与 CAPA 的筛选列表，不展示无来源的静态样本数字。
- 检查结果、个人签认、CAPA 建立、根因、措施、接受、验证与关闭控件仅在详情或措施的 `availableActions` 包含对应动作时渲染；只读用户只看到已授权业务数据。
