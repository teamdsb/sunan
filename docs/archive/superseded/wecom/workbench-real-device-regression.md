# 工作平台企业微信真机回归与留痕模板（M5）

> 状态：已取代。本文保留为 M5 工作平台历史模板；M6 及后续四大板块真机回归统一使用 `real-device-regression-matrix.md`。

## 1. 文档定位

本模板用于 M5 工作平台在企业微信 iOS / Android 容器中的真机回归执行与证据留存，目标是让测试结果可复用为上线材料，而不是只停留在口头确认。

## 2. 适用范围

覆盖以下链路：

- OAuth2 登录
- JS-SDK 初始化
- 工作平台首页与模块可见性
- 记录创建 / 详情 / 动作 / 附件上传
- 审批发起 / 审批状态展示 / 审批异常提示
- 打印与导出
- 弱网和会话异常场景

## 3. 设备信息模板

每次回归必须记录：

| 字段 | 示例 |
|---|---|
| 平台 | iOS / Android |
| 设备型号 | iPhone 15 / Xiaomi 14 |
| 系统版本 | iOS 18.x / Android 15 |
| 企业微信版本 | 4.x.x |
| 执行环境 | 测试环境 / 预发布 / 生产 |
| 执行人 | 张三 |
| 执行时间 | 2026-04-22 10:30 |

## 5. 证据留存规则

- 每条核心链路至少保留 1 份截图或录屏。
- 命名建议：`{date}_{platform}_{case}_{executor}`。
- 若使用截图，需能看清模块名、关键状态、时间和设备标识。
- 若使用录屏，需覆盖进入页面、执行动作、得到结果三个阶段。

## 6. 缺陷记录模板

| 字段 | 说明 |
|---|---|
| 缺陷编号 | 与内部缺陷系统或表格编号一致 |
| 发现平台 | iOS / Android |
| 发现版本 | 企业微信版本 + 应用版本 |
| 场景 | 对应回归用例名称 |
| 复现步骤 | 简明步骤 |
| 实际结果 | 真实表现 |
| 预期结果 | 规格要求 |
| 严重级别 | P0 / P1 / P2 |
| 证据 | 截图、录屏、日志链接 |
| 处理状态 | 待修复 / 已修复 / 已验证 |

## 7. 缺陷闭环要求

- P0 缺陷未关闭前，不允许正式上线。
- P1 缺陷需明确规避方案或修复计划。
- 回归结论必须附缺陷汇总和关闭状态。

## 8. 输出物

本轮真机回归至少输出：

- 真机回归结果表
- 截图/录屏证据目录
- 缺陷清单与闭环状态
- 最终上线结论
