## 2. 执行原则

1. 严格遵循 SDD -> TDD -> 实现 -> 验证。
2. 每个工作包必须同时说明 API、DB、state、UI、权限、测试和文档影响。
3. 不修改 M1-M6 历史验收结论。
4. 不覆盖用户未提交的现有改动。
5. 不接通外部监管、AIS、CCTV 系统。
6. 不用静态看板数据代替真实查询。
7. 不在未冻结规格前创建生产表、路由或接口。

## 3. Wave 1：文档、架构与规格基线

### 目标

- 将差距报告转为可执行规格体系。
- 冻结安全领域边界和 M8 非目标。
- 为后续每个 Wave 建立统一验收门禁。

### 产出

- M8 需求、路线图、执行计划和 backlog。
- `docs/specs/safety/README.md`。
- `domain-boundaries.md`、`terminology-and-status.md`。
- 权限、迁移、测试、验收和提示词模板。
- 当前代码差距清单，结论必须附文件和行号证据。

### 验收标准

- 所有新文档具有有效 YAML 状态头。
- 术语、领域对象和 Wave 依赖无冲突。
- 每个后续工作包可定位到计划规格文件。
- `node scripts/generate-doc-inventory.mjs` 可生成清单。
- 除仓库已有问题外，文档索引校验不新增失败。

## 4. Wave 2：数据权限与流程状态链

### 前置

- Wave 1 通过。
- 权限和状态规格已评审。

### 实现范围

- 在后端建立统一策略判定，不以按钮隐藏代替权限。
- 记录查询、详情、动作、附件、打印和导出使用同一授权上下文。
- 支持步骤执行人、协作人、审核人、观察人和代理人。
- 支持全部完成、任一完成、达到人数等多人完成规则。
- 支持退回指定步骤、终止、作废、重开和任务转移。
- 记录管理员敏感数据查看与全部状态动作。

### 验收标准

- 船员跨船舶读取和操作返回 403。
- 非任务参与人无法执行步骤。
- 措施责任人和验证人冲突时按规则拦截。
- 附件和导出无法绕过记录权限。
- PostgreSQL integration 测试覆盖允许与拒绝矩阵。

## 5. Wave 3：证据、打印、导出与移动能力

### 前置

- Wave 2 通过。
- 文件、证据和导出规格已评审。

### 实现范围

- 工作平台全模块及既有采购执行清单详情统一上传、预览、下载和删除/解除关联交互。
- 采购附件删除只解除采购单—文件关联：复用采购草稿编辑权限，二次确认，记录操作人、时间、原因和关联对象；不得删除 OSS 对象或全局文件元数据。
- 企业微信拍照上传接入现有文件服务。
- 签名和定位保存业务摘要、采集人和采集时间。
- 归档证据删除或替换必须审计。
- 工作平台 PDF 返回可预览下载地址。
- PDF 增加业务编号、版本、生成时间和可配置水印。
- 导出任务真实排队、执行、失败重试和结果下载。

### 验收标准

- 不再要求普通用户手工输入文件 ID。
- 采购执行清单详情的授权编辑者可删除已绑定附件；无权或非草稿状态必须拒绝，且删除后文件仍可供其他合法关联使用。
- 拍照、签名和定位在 iOS/Android 企业微信完成真机验证。
- 无权用户无法下载附件、PDF 或导出文件。
- 导出失败可诊断并重试，不返回模拟文件 ID。

## 6. Wave 4：安全主数据中心

### 前置

- Wave 2、Wave 3 通过。
- 主数据规格和迁移方案已评审。

### 实现范围

- 船舶档案关联证书、人员任职和设备。
- 人员档案关联企业微信身份，支持任职有效期。
- 设备档案关联船舶、分类、编码和状态。
- 表单使用受控选择器，不再要求手工输入人员、船舶和设备 ID。
- 支持幂等导入、重复识别、停用和历史引用保护。
- 对既有记录保留原文本并逐步补充规范化引用。

### 验收标准

- 关键主数据唯一约束和外键生效。
- 停用对象不能用于新业务，历史业务仍可读取。
- 导入重复执行不产生重复数据。
- 主数据详情可追溯关联证书和业务记录。

## 7. Wave 5：计划任务、待办与日历

### 前置

- Wave 4 通过。
- 计划任务状态机和消息规则已评审。

### 实现范围

- 计划包含周期、范围、责任人、计划项和生成规则。
- 计划批准或启用后幂等生成任务。
- 待办聚合本人下一步动作，并提供我发起、我参与和已完成。
- 日历展示真实任务及状态，不使用静态排程。
- 支持改期、取消、催办、升级和任务转移。
- 企业微信消息深链到任务详情或具体动作。

### 验收标准

- 重复执行计划生成不会重复建任务。
- 任务状态变更可回写计划完成率。
- 消息重复发送有去重和审计。
- 转移后原责任人不可继续执行，历史轨迹保留。
- 日历数据可由 API 查询和测试复现。

## 8. Wave 6：检查、问题与 CAPA

### 前置

- Wave 5 通过。
- 检查、问题和 CAPA 规格已评审。

### 实现范围

- 法规、公司和船舶检查模板及版本。
- 检查计划生成多人检查任务。
- 每个检查项记录结论、说明和证据。
- 问题统一记录来源、类型、级别、船舶和责任范围。
- 按规则自动生成不符合项或整改任务。
- 支持根因分析、纠正措施、预防措施和验证。
- 逾期升级、返工、有效性评价和关闭。
- 既有隐患、自查、检验和海事安检保留来源并接入。

### 验收标准

- 多人检查满足完成门槛后才可汇总。
- 自动转单具备幂等键和失败补偿。
- 问题关闭前必须满足证据、措施和验证规则。
- 重大问题不能由普通执行人直接关闭。
- 统计可追踪到原检查项和 CAPA。

## 9. Wave 7：迁移、联调、上线与验收

### 前置

- Wave 1-6 均通过。
- 无未关闭 P0 缺陷。

### 实现范围

- 存量记录分类、映射、迁移和只读兼容。
- 迁移脚本支持演练、校验、回滚和重复执行。
- 完成权限、任务、证据、检查和 CAPA 全链路测试。
- 完成企业微信 iOS、Android 和桌面端回归。
- 更新生产配置、运行监控、操作手册和培训材料。
- 建立 M8 上线包和 Hypercare 记录。

### 验收标准

- `make test-api`、`make test-web`、API/Web build 和 OpenAPI 校验通过。
- 迁移前后记录数量、关联和状态核对通过。
- 真机可完成“计划 -> 任务 -> 检查 -> 问题 -> CAPA -> 验证关闭”。
- 回滚演练和恢复时间有记录。
- M8 验收证据可由第三方按索引复核。
