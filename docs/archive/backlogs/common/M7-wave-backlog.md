# M7 分 Wave 实施清单：上线体验与导航修复（历史归档）

## 1. 使用说明

M7 已于 2026-07-10 完成并归档。本文保留 `M7-execplans.md` 的工程展开和完成时的工作项，不再作为实施清单。

优先级：

- `P0`：阻断当前产品可用性或核心链路。
- `P1`：主流程可用但体验、可理解性或一致性明显不足。
- `P2`：增强项，不得阻塞 P0/P1。

## 2. Wave 1：M1 与通用上传修复

| ID | 优先级 | 层次 | 工作项 | 验收重点 |
|---|---|---|---|---|
| `M7-W1A` | P0 | Repro | 复现上传报错并定位影响范围 | 至少覆盖 `/my`、采购附件、工作台附件入口 |

## 8. 最低验证矩阵

| 范围 | 必跑命令或证据 |
|---|---|
| 文档 | `node scripts/generate-doc-inventory.mjs`、`node scripts/check-doc-index.mjs`、`git diff --check` |
| 上传/API | `pnpm --filter api test:unit` 或受影响 integration、`pnpm --filter api build` |
| 前端 | `pnpm --filter web test`、`pnpm --filter web build` |
| OpenAPI | 变更的 YAML 逐个 `npx swagger-cli validate` |
| 企业微信 H5 | 直达、认证恢复、返回、上传、PDF、导航和弱网证据 |

## 9. 不做事项

- 不启动 M8/M9 安全管理业务。
- 不修改 M1-M6 历史归档验收结论。
- 不用静态演示或截图替代真实上传、PDF、路由和导航验证。
- 不绕过 OSS 预签名上传规格。
- 不为导航问题硬编码只适配单一屏幕或单一入口。
