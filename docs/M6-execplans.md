## Wave 1：需求冻结与高保真收口

### 目标

- 将“差距分析”拆解为可开发、可验收、可排期的 M6 范围。
- 把工作平台所有模块从“模板名称”细化为“真实业务样表 + 字段 + 流程 + 打印 + 统计”。
- 冻结企业微信正式发布所需的生产清单、UAT 清单和上线材料清单。

### 产出

- `docs/requirements/M6-全量兑现与完美上线.md`
- `docs/execplans.md`
- `docs/M6-execplans.md`
- 工作平台模块级高保真补充规格
- 企业微信生产发布清单、UAT 清单、上线材料目录

### 验收标准

- 每个工作平台模块都有明确的真实业务输入来源。
- `财务板块`、`海图更新` 不再只停留在边界描述，而是进入可实现规格。
- M6 的“完成”定义与“完美上线”定义明确且可验收。

## Wave 2：台账类与作业闭环类模块高保真化

### 实现范围

- 台账类模块：
  - 总经办：岗前培训、会议管理、安全月活动、年度工作计划
  - 业务部：签船记录表、船舶动态记录表
  - 船务部：船员培训学时统计、船舶演练系统、值守记录系统、岸基叫应、船员会议记录、案例警示学习
- 作业闭环类模块：
  - 业务部：作业人员签到台、接收工作组操作流程、围油栏、垃圾/污油水/生活污水接收
  - 工作组：中船工作组、平陆运河工作组五步作业闭环
- 打印、查询、归档和模块级独立页面标准化。

### 验收标准

- 模块不再只依赖通用动态页面，具备独立业务页面和高保真字段录入。
- 纸质样表、线下记录本和系统字段的一致性完成核对。
- 列表、详情、录单、动作、附件、打印、归档均可在模块级页面跑通。

## Wave 3：检查整改、统计与审批/资产模块高保真化

### 实现范围

- 检查整改类模块：
  - 总经办：安全隐患排查管理
  - 船务部：船舶自查排查、船舶检验、密闭空间、污油水接收作业、海事安检系统
- 考勤统计类模块：
  - 财务部统计中心
  - 船务部船员考勤
- 服务资产与审批类模块：
  - 船务部：船舶设施设备保养、燃油加注、航次计划审批
  - 后勤部：仓库、办公室、食堂、宿舍、车辆维修保养

### 验收标准

- 检查整改前后照片、整改闭环、审核结论、打印归档全部可用。
- 统计中心与船员考勤不只是通用记录页，而是具备完整业务页面、口径说明、导出与对账入口。
- 服务资产和审批类模块实现真实业务字段、真实审批映射和归档检索。

## 完成定义

M6 只有在以下条件全部成立后才算完成：

- `docs/需求文档.md` 四大板块无未兑现核心功能。
- 工作平台各模板模块达到高保真业务成品标准。
- `财务板块`、`海图更新` 从遗留规格变为正式交付模块。
- 企业微信生产配置、审批模板、真机回归和上线材料全部闭环。
- 全量测试、冒烟测试、UAT 和正式发布验收全部通过。
