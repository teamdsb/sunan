# 全系统前后端接口与功能回归

## 范围与结论口径

基于 `cce7d0e` 后的本次工作树，核对整个系统，而非只检查 M9。范围包括认证、全部用户与通知设置、企业资料/制度、证照/提醒、船舶监控、办事、采购、主数据、工作台、计划任务、检查/CAPA、附件、审批、统计及导出。没有新增 migration。

当前源码共 19 个 Controller、233 条方法/路径组合；前端识别到 195 处调用，另有 5 处统一请求或签名 URL 转交。前端路径/方法无未匹配、未解析项，后端无重复路由。实际 Nest Swagger 同为 233 条，与源码逐项一致。

逐接口 HTTP 状态、前端调用点和证据文件保存在 [JSON](../../output/api-audit-2026-11-17/route-coverage.json) 与 [CSV](../../output/api-audit-2026-11-17/route-coverage.csv)；[静态清单](../../output/api-audit-2026-11-17/source-contracts.json)包含 DTO 参数声明和调用源码位置。累计采集 2,995 条本地合成/浏览器请求，233/233 路由都有 2xx 证据；最终完整集成及浏览器批次覆盖 231 条，其余 2 条由先前真实浏览器请求覆盖。静态对应只证明路径和方法，HTTP 成功也不代表全部业务分支或真实企业微信验收完成。

## 已修复问题

| 问题 | 修复后行为与验证重点 |
|---|---|
| 人工部门选项的名称只用于预览，实际自动角色未按部门字典生效 | 授权计算异步查询当前企业部门字典；登录、旧 JWT、刷新、业务筛选和收件人等待同一结果。覆盖自定义部门 ID、跨企业隔离及部门更名立即生效 |
| 普通用户能凭 ID 查看列表范围外的人员详情 | 详情与列表采用一致的本人/管理权限，拒绝越权读取；保留合法详情和脱敏规则 |
| 知道存储 key/fileId 可以绕过业务权限下载或跨记录绑定文件 | 通用下载只允许本人未绑定临时上传；普通成员新绑定需满足临时文件权限，事务内排序锁文件；已有关联可幂等保留。覆盖 callback、企微媒体重放及自查照片重用 |
| 已保存检查/CAPA 证据和工作台签名缺少可用的查看链路 | 检查/CAPA 增加两条业务下载接口，工作台签名复用所属记录下载入口；先验业务读取权再验实际文件关系。详情只返回安全文件信息，UI 可查看已保存证据；绑定成功清临时上传状态 |
| 采购日期编辑崩溃、数字表单提交字符串、主数据编辑残留 | 日期在 API 字符串和 Dayjs 间正确转换；数字使用数值控件；切换主数据记录重置表单，设备返回 categoryCode、人员返回可见 remarks，并验证保存后重读 |
| 两个采购审批页点击取消仍发送同意请求 | 取消 prompt 后终止提交，确认/退回仍正常执行 |
| 办事删除后的操作审计消失，分类权限过滤后的分页和 total 不准 | 在权限范围内包含软删除对象查询审计，并在分页前限定可管理范围；页面支持审计翻页 |
| 首页漏掉逾期/部分投递状态提醒，详情确认按钮与后端权限不一致 | 首页覆盖活跃提醒状态，按钮采用后端 canAcknowledge，不以可见性代替可确认权限 |
| 普通读者看不到企业资料/制度正文，已发布制度可绕过内容只读约束 | 读者展示正文；已发布过的版本冻结内容和附件，允许纯废弃操作，草稿正常维护 |
| 工作台部分动作只检查可读权限，整改重做和步骤状态不一致 | 所有动作执行操作授权和状态校验；只完成当前步骤，重做/退回重开后续步骤，完成执行后才能审核关闭 |
| 检查模板草稿被当作当前发布版本，部分任务生成入口没有检查实例 | UI 可发布模板，计划只使用已发布版本；所有生成入口在同事务创建检查快照，保持幂等；通用完成按钮不能绕过检查结果与个人签认 |
| CAPA 措施责任人无法发现并打开自己的工作 | 允许读取所属问题与措施，保留独立管理/验收权限，不授予全局管理能力 |
| 已取消任务仍能保存、签认或汇总检查，汇总可能把任务恢复为完成 | 任务动作与检查写入统一 task 锁顺序，事务内重读双方终态；取消同步检查状态，覆盖历史不一致状态及并发取消；完成汇总仍可幂等重放 |
| 企业微信审批 SDK 取消/失败后原审批编号无法安全恢复 | 使用原 thirdNo 核对已有实例；已存在则打开原审批，未知保持 pending_confirmation 并返回明确 409，避免新编号重复发起 |
| 考勤财务对账接口返回 queued 但无 worker、持久化结果或调用方 | 删除假接口 `POST /workbench/statistics/attendance/reconcile`、对应 DTO/服务和 OpenAPI；请求返回 404，财务模板对账不再列为已实现能力 |
| 个人“推送通知”开关保存成功但没有发送消费者使用 | 去掉无效果 UI 开关，说明证照/采购/任务通知由业务规则控制；历史字段保留兼容并标记 deprecated，不误停业务必需通知 |
| 已归档企业资料可凭已知 ID 读取或签名下载 | 详情和附件下载统一检查归档可见性；普通成员返回 404，系统管理员仍可查看和下载；写入归档的操作响应保持可用 |

上述修复保留 env 管理员唯一来源、人工授权不被同步覆盖、通知错误覆盖不回退主应用、用户软删除及附件引用保护等既有规则。文件安全及下载复核见 [独立记录](../../output/api-audit-2026-11-17/inspection-download-review.md)。Auth 异步调用链另经只读复核，最终完整测试由主任务统一执行。

## 浏览器与现场边界

本轮使用真实 React → Nest → PostgreSQL 完成采购草稿日期/金额保存重读、通讯录同步、人工空角色保存并再次 OAuth 核对，以及工作台数值字段提交重读。浏览器使用合成管理员/成员，未用前端 mock route 代替后端。

具体截图、命令及本轮最终汇总见证据目录。浏览器只覆盖代表链路；完整前端组件测试与逐接口 HTTP 补足其余自动化范围，不能解释成已人工点击全部按钮。

React Router/Ant Design 开发弃用提示、PG 查询并发弃用提示如实保留；旧浏览器会话曾出现 token 过期后刷新请求及 favicon 404，不宣称零控制台告警。首次集成批次中工作台附件分类预签名收到 401；相同用例独立全绿，销毁本地合成 API 后干净全量复跑也全绿，暂未定位可重复的产品故障。该波动记录保留，不隐去首次失败。

下列项目仍需实际环境证据，本轮没有完成：

- 企业微信主应用全企业目标成员核对；局部可见或完整性未验证不能算全目录通过。
- 主应用/独立通知应用真实 token、可见范围、真实送达、JS-SDK 媒体与审批原生页面、真实签名/加密回调。
- iOS、Android、桌面企业微信的实际工作台、定位/签名、弱网与打印体验。
- 生产迁移/恢复、兼容镜像、密钥/多实例切换及生产部署。
- 审批 thirdNo 查询的“确实不存在”外部语义尚未获得可验证契约；未知状态只能核对/人工处理，尚未提供无证据的重新发起入口。已存在实例可按原编号恢复打开。

M9 增加的是成员同步与用户管理、平台部门/业务角色与停用、授权历史及重新认证一致性、可选通知应用和投递排查。原四大业务入口保留，但权限收口、撤权及已发布内容只读会拒绝以前错误放行的操作。本次回归覆盖既有功能，不能承诺任意生产数据和外部环境下绝无错误。M9-W5 的现场矩阵继续以 [原验收](../acceptance/M9-wave-5.md)为准，本报告不将未执行项标成通过。
