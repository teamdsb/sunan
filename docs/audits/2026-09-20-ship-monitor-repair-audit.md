# 船舶监控修复与相关功能核查

## 范围与结论

按用户确认，仅 `system_admin` 可配置监控，复用现有船舶选择器。已修复监控新增及相关管理链路，并核查船舶主数据、首页统计以及原始目标中尚未闭环的考勤、学习和燃油功能。本记录基于本地工作树，不代表已部署到生产或已通过真实企业微信、第三方视频平台验收。M9 继续暂停。

## 已修复的问题

| 问题与影响 | 修复结果 |
|---|---|
| 新增要求手填船舶 UUID，输入船名会被接口拒绝，页面没有明确错误反馈 | 改用可搜索的有效船舶选择器；提交实际 ID，显示成功或失败信息，失败保留输入 |
| 管理页面缺少编辑、启停、删除操作 | 补齐名称、船舶、地址、访问模式、排序、启用状态编辑，以及删除确认与列表刷新 |
| `activeOnly=false` 被转换为 true，停用记录无法正常管理 | 显式解析布尔查询参数；管理员可查看全部，普通成员只读启用项；详情接口应用同样的限制 |
| 船舶或角色切换时可能短暂显示之前缓存的监控 | 查询参数包含船舶和权限筛选，使用当前查询数据；普通成员额外过滤停用项 |
| 无效船舶、重复名称、空白名称、非法地址和排序值缺少可靠反馈 | 创建、换船、启用检查船舶有效性；重复名称含并发冲突返回 409；校验名称、HTTP(S) 地址及整数排序 |
| 原船舶停用或删除后旧监控可能无法清理 | 仍允许停用、删除旧入口；返回船舶名称与编码，软删除后仍能识别 |
| 嵌入模式没有可操作的预览 | 提供嵌入预览及外部打开入口；实际平台是否允许嵌入取决于对方配置 |
| 列表或船舶选择器请求失败缺少恢复方式 | 提供错误提示及重试入口 |
| 主数据保存成功后仍提示失败 | 修正 RTK mutation 的调用顺序，在等待结果前调用 `.unwrap()`；覆盖新增和编辑回归 |
| 船舶表单提供接口不接受的“报废”状态 | 船舶仅提供有效、停用选项，与 API 契约一致 |
| 首页把配置了监控的船舶显示为“在线船舶” | 改为“监控船舶 / 艘已配置监控”，避免把配置数量误认为实时在线状态 |

监控修复无需数据库结构迁移。关联船名和编码通过批量读取主数据返回，船舶改名后随之更新。

## 验证证据

- API 单元测试：26 个套件、147 项通过。
- PostgreSQL 集成测试：19 个套件、112 项通过，使用独立 Testcontainers 数据库。
- Web 测试：59 个文件、262 项通过；合计 521 项。
- 回归验证：原 DTO 在新增校验用例中有 7 项失败，原服务/控制器在监控集成用例中有 7 项失败，原主数据保存实现也被回归用例复现；修复后相关用例通过。
- 浏览器使用真实 Nest 监控和主数据模块、独立 PostgreSQL，仅模拟认证。已验证选择船舶新增、编辑、嵌入预览、启停、删除确认、普通成员只读和外部打开；390 × 844 视口无水平溢出。
- 浏览器截图保存在 `output/playwright/ship-monitor-repair/`；自动化日志保存在 `/tmp/sunan-monitor-check/`。临时认证服务和预览页面已清理，不随交付保留。
- 最终 `pnpm build` 通过（Web 与 API）；监控 OpenAPI 经 `swagger-cli validate` 校验通过，277 份 Markdown 索引校验及 `git diff --check` 通过。

## 扩查发现的剩余缺口

以下是监控修复结束时的缺口快照；用户随后要求一起补齐，当前实现与验证见 [考勤、个人学习及燃油补齐记录](2026-09-20-workbench-business-completion.md)。下表保留修复前证据。

| 优先级 | 功能 | 当前源码证据与影响 |
|---|---|---|
| 高 | 考勤统计导出 | `WorkbenchService.runAttendanceExport` 与 `buildAttendanceWorkbook` 只输出月份、部门编码、生成时间，没有考勤明细或人员工时。XLSX 文件格式有效，但不能作为完整考勤报表使用。`getAttendanceStatistics` 当前主要统计记录数及上午/下午次数。 |
| 中 | 培训学时与案例学习 | `shipping_training_hours` 记录船舶、船员名单、主题和总学时，`shipping_case_study` 记录学习对象及学习情况；目前是手工台账，未找到按个人自动累计学习进度与完成率的链路。此项为自动化能力缺口，不等于台账新增失效。 |
| 中 | 燃油月报与余量提醒 | `shipping_fuel_bunkering_approval` 要求手填剩余油量、月油耗和月报月份；未找到自动计算月耗、生成月报及低油量提醒的完整链路。 |

上述实现均位于 [workbench.service.ts](../../apps/api/src/modules/workbench/workbench.service.ts)，可通过表内方法名或模块编码定位。历史原始目标对照见 [2026-09-07 核查](2026-09-07-original-goal-audit.md)；本次以当前源码重新确认，未把历史文件中的结论直接当作现状。

## 未覆盖的现场验证

- 真实企业微信授权、审批回调与企业微信三端使用未在本轮现场验证。
- 第三方视频平台的登录、播放和嵌入限制未使用真实地址验证；浏览器预览用的是本地 HTML 页面。
- 自动化测试通过不等于全部业务目标已实现，上表三项的后续验证以补齐记录为准。
